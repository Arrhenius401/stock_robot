# 会话生命周期与配置界面设计

## 背景与目标

本次改动统一命令行进度条表现，消除静态界面中无消息会话的持久化记录，并增加可视化配置管理界面。目标是让用户在不编辑 YAML 的情况下完成常用配置，同时避免凭据泄露和会话垃圾数据。

## 范围

1. `analyze` 与 `index` 复用 `run` 的 Rich 启动进度条视觉与生命周期：Spinner、描述、横向进度条，任务结束后自动消失；不显示完成计数。
2. 新建会话仅在浏览器内创建临时状态；首条消息发送时才持久化。连续点击新建会话复用同一临时状态，并清空尚未发送的输入内容。
3. 清理兼容旧版本产生的空会话。删除“清空会话”功能，保留删除会话。
4. 增加静态界面的配置页、读取与受控更新 API。

## 非目标

- 不开放行业评分 YAML、报告模板、RAG/SQLite/LangGraph 内部参数或状态目录路径编辑。
- 不改变分析管道阶段、报告格式、CLI 的 `config get/set` 命令。
- 不支持在运行中的 Web 服务内热更新监听主机和端口。

## 会话生命周期

### 临时会话

- 前端启动时或用户点击“新建会话”时，只生成内存临时会话 ID 和空消息/成果缓存；不调用创建会话接口，不写 SQLite。
- 用户连续点击“新建会话”时，如果当前会话尚未持久化，复用该临时会话、保持空白聊天历史，并清空输入框中尚未发送的内容。
- 历史会话间切换后再新建，创建新的临时状态；临时状态不进入侧边栏会话列表，也不会在刷新后恢复。
- 临时会话禁止重命名、删除和查看历史成果；这些操作只针对服务端已持久化 ID。

### 首次发送与持久化

- 聊天首发携带临时 ID；后端把它视为未持久化的客户端关联标识，并生成新的真实会话 ID。
- 后端在保存第一条用户消息前创建真实会话，后续 SSE 与 REST 返回真实 ID；前端原子地将消息、成果、运行状态和当前会话引用从临时 ID 迁移至真实 ID。
- 用户直接发送而没有预建临时会话时，仍沿用后端生成真实 ID 的兼容路径。
- 原有持久化会话 ID 的请求保持既有语义。

### 空会话清理与功能收敛

- `SessionStore` 初始化时删除消息数量为零的会话，并借助外键/显式删除同步清除其成果，完成旧数据迁移。
- 会话列表读取前也执行同一清理，以覆盖程序运行期间遗留的异常空记录。
- 删除聊天快速操作中的“清空会话”，移除对应前端 API 调用与 `POST /api/v1/sessions/{session_id}/clear` 服务端路由和测试；保留删除会话。

## 配置界面

### 信息架构

在侧边栏增加“配置”导航项和独立视图，分为以下分区：

| 分区 | 可编辑字段 |
| --- | --- |
| LLM 设置 | provider、model、enabled、api_key、base_url、temperature、max_tokens、retry_times、timeout_seconds |
| 数据与缓存 | disclaimer_accepted、daily/quarterly/news 缓存时长 |
| 服务设置 | api.host、api.port |
| 推送设置 | enabled、max_symbols_per_subscription、邮箱与企业微信配置 |
| 信号策略 | attack/watch 阈值与 attack/watch/defend 的操作、仓位文案 |

页面只读展示项目状态目录和配置文件绝对路径。不会展示内部存储路径、默认配置合并实现、行业评分规则和报告模板位置。

### API 与校验

- 提供获取页面配置的 API：以白名单字段构造响应，不返回完整内部配置对象。
- 提供更新 API：仅接受白名单字段的局部更新，深度合并到 `Config.data` 后写回 `.stock_robot/config.yaml`。
- 后端执行类型、范围与关联校验：缓存时长和端口为正整数；温度、最大 Token、超时与重试次数为合理数值；攻击阈值必须高于观察阈值；信号操作/仓位为非空字符串。
- 对 host 做非空字符串校验，但不尝试在保存期间重启 Web 服务。保存 host/port 后，界面提示重启 `stock-robot run` 后生效。
- 保留 CLI 与 YAML 文件直接编辑的兼容性；所有入口读写同一个 `Config` 文件。

### 凭据保护

- API Key、SMTP 密码、企业微信 Secret 的读取响应默认只返回首尾各 4 至 5 个字符、中间以星号替代的脱敏值和“是否已配置”状态。
- 页面默认显示脱敏值，并使用睁眼/闭眼图标作为“显示完整内容”切换。完整内容仅在当前页面内存中短暂展示，不写日志或持久化到浏览器存储。
- 为支持显示开关，读取 API 需受本地服务边界保护；页面通过显式请求取得完整值，且不得将其写入 DOM 以外的全局状态。
- 保存表单时，密钥输入为空代表保持原值；只有提交非空新值时才覆盖现有值。
- 该遮罩机制用于防止肩窥和意外截图，不构成访问控制；能够访问本机 Web 服务和浏览器开发工具的用户仍可能读取完整凭据。若服务未来暴露到非受信网络，必须先引入认证机制，配置页不得直接启用。

## CLI 进度条

- 抽取 `run` 使用的 Rich `Progress` 构造为共享辅助方法。
- `analyze` 与 `index` 保持当前 `on_progress(stage, current, total, label)` 回调语义，改为调用共享辅助方法创建任务并更新。
- 上下文退出时使用 `transient=True` 清理终端进度行。错误仍由各命令现有的顶层错误处理报告。

## 测试与验收

- 单元测试覆盖共享进度构造、`analyze`/`index` 的阶段更新、无完成计数以及完成后不遗留进度内容。
- 会话测试覆盖临时会话不落库、连续新建复用、首条消息生成真实 ID、旧空会话清理、已持久化会话兼容和“清空会话”路由不存在。
- API 测试覆盖配置白名单、局部更新、无效值拒绝、host/port 重启提示所需字段及密钥脱敏/保留原值语义。
- 静态模块测试覆盖新建会话输入清空、会话缓存 ID 迁移、配置表单渲染、眼睛图标切换和密钥保存。
- 真实启动 `stock-robot run`：验证进度条完成后消失；新建空会话刷新后不恢复；保存配置后普通配置被下一次请求读取，服务地址/端口显示重启提示。
