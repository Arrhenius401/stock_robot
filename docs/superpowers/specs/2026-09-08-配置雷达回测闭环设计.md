# 配置雷达回测闭环设计

日期：2026-09-08
关联设计：[配置雷达设计](2026-09-05-配置雷达设计.md)

## 背景

配置雷达 ETF MVP 已能按月度轮动生成可审计回测：信号使用当日及以前日线、下一交易日开盘成交，输出净值、成交和累计收益、年化收益、年化波动率、夏普比率、最大回撤。

本次补全不改变该策略的投资逻辑，而是让结果具备可比较、可解释和可复跑的研究条件。当前 `--benchmark` 仅校验行情可用性并写入运行清单，未生成基准净值或相对指标；交易成本、调仓规则也未被完整地作为策略快照保存。它们会使“回测结果”容易被误读为可直接比较的结论。

## 目标与非目标

### 目标

1. 让每次 ETF 雷达回测都能与三类明确、可复现的基准同时比较。
2. 将影响回测结果的执行和成本假设配置化，并完整固化到产物。
3. 提供跨市场阶段的稳健性验证，避免只以单一时间区间判断策略。
4. 让 CLI、API、配置雷达详情页和报告库读取同一份已完成产物，不在查看结果时重新请求行情或运行回测。

### 非目标

- 不承诺策略会跑赢基准或获得稳定正收益。
- 不引入自动交易、模拟账户、个性化仓位建议、盘中/高频回测。
- 不在本期启用股票池；`asset_type: stock` 的数据、因子、复权和 point-in-time 财务数据另行设计。
- 不在本期加入基于结果调参的自动优化、止损择时或预测模型。

## 范围与优先级

| 优先级 | 能力 | 首期交付定义 |
|---|---|---|
| P0 | 多基准比较闭环 | 同时生成货币、权益、全债三条基准净值，以及相对指标和可切换曲线。 |
| P0 | 配置快照 | 策略、成本、调仓和基准选择均有版本化配置，并写入 `manifest.json`。 |
| P0 | 完整产物与接口 | 摘要、双曲线、成交、换手和警告可由 API/Web 读取。 |
| P1 | 稳健性报告 | 基于固定窗口生成多段独立结果，显示结果分布，不挑选最佳区间。 |
| P2 | 更细执行约束 | 最小交易单位、买卖价差、停牌/异常行情、ETF 特定费率。 |
| 后续 | 股票池回测 | 独立股票评分与 point-in-time 数据链，不复用 ETF 规则。 |

## 基准比较

### 基准选择

每次 ETF 雷达回测固定同时计算以下三条人民币计价指数，界面不允许将其中任何一条作为隐藏的“唯一主基准”：

| ID | 名称 | 代码 | 用途 |
|---|---|---|---|
| `money_fund` | 中证货币型基金指数 | `H11025` | 衡量持有现金或低风险流动性资产的机会成本。 |
| `csi_300` | 沪深 300 | `000300` | 衡量相对国内权益市场的表现。 |
| `csi_all_bond` | 中证全债指数 | `H11001` | 衡量相对低波动债券资产的表现。 |

三条指数共用一份版本化 `radar_benchmarks` 配置，避免依赖单股回测的全局配置。它们即使面对海外 QDII ETF 池也按人民币计价保留：目的是比较本地投资者可见的机会成本，不是声称它们与海外风险暴露完全同质。

执行前必须取得策略预热期至结束日的三条基准日线。任一基准行情无法覆盖正式回测区间，或无法与策略交易日对齐时，整次运行失败，不创建成功产物，也不得用零收益代替。CLI 不再以单一 `--benchmark` 决定本次结果；如保留该参数，只能用于指定界面和终端的默认展示项，不能减少产物中的三条基准。

### 净值与指标

策略与每条基准在正式回测首日统一归一化为 `1.0`。基准采用收盘到收盘持有净值；策略仍采用“月末信号、下一交易日开盘成交”。不把基准用于选标、打分或调仓。

除既有指标外，`summary.json` 增加：

- 每条基准的 `累计收益`、`年化收益`
- 对每条基准的 `超额累计收益`、`超额年化收益`
- 对每条基准的 `相对净值最大回撤`
- `换手率`、`交易次数`

超额收益定义为策略与对应基准归一化净值的差异；相对净值定义为策略净值除以对应基准净值。报告必须同时展示策略和三个基准的绝对表现，不能只展示超额值。

## 策略与成本配置

策略 YAML 保留评分权重和窗口，并新增以下显式字段：

```yaml
rebalance: monthly
execution: next_open
selection:
  per_category: 1
  allocation: equal_weight
cost_profile: etf_default
```

成本档独立保存，首期 `etf_default` 至少含 `commission_rate` 与 `slippage_rate`；买卖双边计入佣金和滑点，不使用股票卖出印花税。执行价为开盘价在滑点后的价格：买入上调、卖出下调。成本档的完整值而非仅名称必须写入运行清单。

若某次调仓日没有可交易开盘价，标的保持上一有效仓位；若没有既有仓位或没有任何可交易候选，资金保留为现金。每个此类降级都写入 `warnings` 和交易明细，禁止静默忽略。

## 产物与 API 契约

每次成功回测仍原子写入：

```text
reports/radar_backtests/<asset_type>/<strategy_id>/<universe_id>/<YYYY-MM>/<run_id>/
├── report.md
├── summary.json
├── manifest.json
├── equity_curve.csv
└── trades.csv
```

`equity_curve.csv` 固定包含 `date`、`strategy_equity`、`money_fund_equity`、`csi_300_equity`、`csi_all_bond_equity`，以及三组对应的相对净值列；可追加 `cash_weight`，但不修改已定义字段的语义。`trades.csv` 增加调仓前后目标权重、成交滑点和费用字段。`manifest.json` 记录池版本、策略完整快照及指纹、成本完整快照、三条基准规格、实际数据范围、数据提供者、警告和生成时间。

`GET /api/v1/radar/backtests/latest?universe_id=...` 保持只读，仅返回最近一次完整产物的摘要、策略与三基准净值曲线、交易统计和可展示警告。没有产物返回 404；损坏或不完整产物不返回部分成功数据。

配置雷达详情页展示最近一次同池、同策略的回测摘要，并明确回测区间、成本与“历史表现不代表未来收益”。页面提供“货币基金 / 沪深 300 / 中证全债”分段切换控件；切换只选择已经写入产物的一组基准指标和相对曲线，不触发回测或网络请求。报告库详情页读取相同产物，展示策略、所选基准和相对净值曲线及交易明细。

## 配置雷达标的详情页

配置雷达列表只承担池选择、快照状态、筛选和排名浏览。用户点击任一 ETF（未来也包括受限股票池的股票）后，应用进入独立的详情视图，而不是在列表右侧展开抽屉或侧边栏。

左侧全局导航始终保留；右侧主内容区由列表完整切换为详情，以获得与报告详情一致的阅读宽度和信息层级。详情顶部从左到右依次为：仅含左向 Chevron 图标的“返回配置雷达”按钮、标的名称和代码、资产类型/所属池/快照日期元信息，以及研究免责声明。返回按钮必须可键盘聚焦，并具有可访问名称。

详情页依次展示：

1. 总评分、分类排名、研究等级、价格与成交额等摘要；
2. 评分依据：每个因子的原始值、分类内分位、权重、得分贡献、评分配置 ID 与版本；
3. 风险和数据质量：行情时间、数据源、历史覆盖、`fresh`/`stale`/`failed` 状态与降级原因；
4. 同池同策略的最新回测：策略指标、三基准切换控件、策略/所选基准/相对净值曲线、成本和区间说明；
5. 仅在本标的是该次回测实际持仓或成交对象时出现的相关成交记录。若当前产物是池级回测而非单标的表现，页面必须标明这一点，不能把池级指标表述为该标的的独立历史收益。

路由以稳定的池 ID、完成快照 `run_id` 和标的代码表达，例如 `#radar/cn_hk_etf/<run_id>/510300`。浏览器前进/后退与返回按钮均回到原雷达列表，并恢复先前的池选择、类别筛选、排序和滚动位置；详情标的或快照不存在时显示可恢复的错误页和同一返回入口。进入详情只读取已完成快照和已有回测产物，不发起刷新、回测或上游数据请求。

## 稳健性验证（P1）

新增独立命令，例如：

```text
stock-robot radar backtest-walkforward \
  --universe cn_hk_etf --strategy core_rotation_v1 \
  --start 2020-01-01 --end 2025-12-31 --window-years 2
```

该命令按固定、连续且不重叠的窗口运行相同策略和相同成本档；每段都生成独立可审计子产物，并输出汇总表。汇总至少给出每段的策略/基准收益、超额收益、最大回撤、夏普和交易次数，以及正超额区间占比。

窗口边界、策略版本和基准在运行前固定；禁止根据各段结果回头改变权重、窗口或挑选展示区间。样本不足的窗口明确标为不可用，不纳入汇总平均。

## 风险边界

- ETF 的历史前复权日线及成交额只用于个人研究；数据源差异、复权方式与缺失行情都可能影响结果。
- 当前模型不模拟申赎、最小申购单位、市场冲击、停牌、涨跌停和实际账户税费；报告必须披露这一限制。
- 评分是分类内相对排序，不是对基金基本面、跟踪误差、成分重叠或未来收益的预测。
- 历史回测、基准比较和稳健性报告用于否定或约束假设，不能构成收益承诺。

## 验收

1. 固定日线夹具中，基准与策略从同一基点开始，所有相对指标可手工复算。
2. 基准缺失、日期无法对齐、策略/成本配置非法时，以非零退出失败且不留下成功目录。
3. 成本、滑点、下一交易日成交、无法成交保留仓位/现金、换手和警告均有单元测试。
4. 产物必须同时存在五个文件才可被 API、详情页和报告库读取；字段缺失或 CSV 损坏时明确报告不可用。
5. P1 的固定多窗口夹具覆盖至少一个正超额、一个负超额和一个数据不足窗口，验证汇总不选择性忽略负样本。
6. 前端验收覆盖：从雷达列表进入独立详情、左侧导航仍可用、三基准切换不产生网络数据请求、浏览器前进/后退与返回按钮均恢复原列表状态，以及快照/标的缺失时可返回的错误状态。
