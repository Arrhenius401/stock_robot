# 报告库设计

## 目标

在现有静态单页应用新增“报告库”视图，使用户能够浏览工作目录 `reports/` 中已经持久化的个股分析报告、指数分析报告和回测报告，而无需重新运行分析或回测。

报告库只读本地历史产物。它不修改报告文件、不触发分析任务，也不把报告文件直接暴露为任意静态路径。

## 用户界面

在现有应用左侧导航增加“报告库”入口，沿用当前浅色工作台、左侧导航、蓝色主按钮、`analysis-entry` 查询条、`panel` 卡片和报告正文样式。顶部首行比现有紧凑栏略高，保留 `Stock Robot` 与当前视图标题，不在右上角展示全局“分析”搜索模块。

- 报告库列表页只负责搜索、筛选和展示报告集合，不在列表页嵌入详情，避免报告很多时详情被挤到下方或需要长距离滚动。
- 列表页主区顶部提供关键词搜索、显式刷新、“全部、个股、指数、回测”类型筛选，以及生成时间/月度等轻量排序或范围控制。下方以自适应卡片网格展示报告，卡片展示类型、代码/名称或策略、生成时间和“打开详情”入口。
- 报告详情页从列表页进入，作为同一个静态应用内的独立视图状态展示。标题行最左侧是仅含左向 Chevron 图标的返回按钮，旁边是报告标题和元信息，右侧保留下载入口。
- 个股和指数详情页渲染各自 Markdown 正文。
- 回测详情页提供“报告正文、净值曲线、交易明细”三个页签。正文渲染 `report.md`；净值曲线基于 `equity_curve.csv` 在浏览器绘图；交易明细显示 `trades.csv` 表格。
- 回测详情页顶部展示累计收益、最大回撤、交易次数、夏普比率等摘要指标；缺失的摘要字段显示占位，不阻塞正文阅读。
- 空状态在列表页展示：没有历史产物时说明 `reports/` 目录为空；筛选无结果时说明当前筛选条件下没有报告。详情 ID 不存在时展示可返回报告库的错误状态。

列表刷新由用户显式触发，避免每次切换视图递归扫描磁盘。

## 后端边界与 API

新增独立的报告库服务模块，唯一负责枚举与读取持久化产物；FastAPI 路由只负责参数校验、转换 HTTP 错误并返回 JSON/文件响应。

`GET /api/v1/reports`

- 可选 `type=stock|index|backtest` 与 `query` 参数。
- 仅扫描 `reports/stock/`、`reports/index/` 以及 `reports/backtests/`；为兼容旧版产物，也识别历史根目录下的 `<代码>/<YYYY-MM>/*.md` 个股报告。
- 返回扁平的条目摘要：稳定的相对 ID、类型、标题、代码、策略（如适用）、生成时间和是否具备回测附属数据；按生成时间倒序排列。

`GET /api/v1/reports/{report_id}`

- 读取一个已枚举条目的详情。
- 个股和指数返回 Markdown；回测额外返回摘要 JSON、净值数据和交易明细，前端按需从同一详情结果渲染页签。
- 不存在或失效 ID 返回 404；文件内容损坏、UTF-8/JSON/CSV 解析失败返回可区分的 422 错误，不影响其它条目。

`GET /api/v1/reports/{report_id}/download`

- 以附件形式返回相应 Markdown 文件。回测下载 `report.md`。

报告 ID 由服务端基于相对路径编码生成，绝不接受客户端提交的文件系统路径。每次从 ID 还原路径时都执行 `resolve()` 并验证其仍位于 `reports/` 根目录，且扩展名和目录结构满足已识别报告类型；因此拒绝 `..`、绝对路径、符号链接逃逸与任意文件读取。

## 产物识别与数据转换

个股和指数报告均由 `ReportFormatter.save()` 写入 `<类型>/<代码>/<YYYY-MM>/<代码>_<时间>.md`，以分类根目录识别类型。遗留个股报告位于 `<代码>/<YYYY-MM>/*.md`，以六码证券代码目录识别。

回测的运行目录固定为 `backtests/<策略 ID>/<代码>/<YYYY-MM>/<运行 ID>/`，只有同时存在 `report.md` 和 `summary.json` 才可列入。`manifest.json` 用于补充策略名称、数据区间和生成信息；`equity_curve.csv` 与 `trades.csv` 缺失时仍可打开正文，但对应页签显示“该次运行未包含此产物”。

服务端将 CSV 解析为 JSON 安全的标量和列数组：净值曲线保留日期、策略净值与基准净值（若存在）；交易明细限制为合理的最大行数并保留列名。避免将任意 CSV 内容作为 HTML 返回。

## 前端实现

新增 `report-library.js` 管理报告库状态、请求、筛选、列表页、详情页、返回行为和错误状态；在 `api.js` 增加三个 API 调用。`app.js` 与 `index.html` 注册新视图，`app.css` 提供列表网格、详情页头部、Chevron 返回按钮、摘要指标、回测页签、曲线和交易表样式。

Markdown 继续复用现有的受控渲染函数；浏览器端仅用 DOM API 建表和绘图，不拼接不可信 HTML。曲线由原生 SVG 绘制，包含策略与基准图例、无数据状态和响应式尺寸，不引入新的前端依赖。

## 错误处理

- `reports/` 缺失、没有可识别产物：返回成功空列表。
- 单个文件无法读取或不符合格式：列表可保留该条目并在详情显示具体的“文件已损坏或不完整”错误。
- API 网络或解析失败：当前视图显示可重试错误，保留已加载列表与当前筛选。
- 当前详情报告在刷新后被删除：详情页说明报告已不存在，并提供左向 Chevron 返回报告库。

## 测试与验收

- 为报告库服务创建临时目录夹具，覆盖三类有效产物、旧版个股路径、排序与筛选、空目录、缺失回测附属文件、损坏 JSON/CSV、未知 ID 和路径穿越/符号链接防护。
- 为 API 路由验证列表、详情、下载响应与错误码。
- 为静态页面测试新增导航、列表页搜索筛选、卡片网格、独立详情页、左向 Chevron 返回按钮、下载入口和回测页签的关键 DOM 行为。
- 通过项目真实启动路径 `./.venv/Scripts/stock-robot.exe api` 启动服务，在浏览器完成一次：进入报告库、打开三类真实报告、查看回测曲线和交易明细、刷新并处理空/错误状态。

## 不在本期范围

- 删除、重命名、移动或重新生成历史报告。
- 云端同步、跨工作区浏览和全文索引。
- 回测指标再计算或交互式策略参数调整。
