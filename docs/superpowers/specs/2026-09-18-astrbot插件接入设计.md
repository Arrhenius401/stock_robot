# AstrBot 插件接入设计（QQ 股票分析）

日期：2026-09-18
关联：新建独立仓库 `astrbot_plugin_stock_robot`（不在本仓内实现，本仓零改动）

## 背景

项目最初的设想是让 agent 接入 QQ。接触 AstrBot 后确定以 AstrBot 为接入载体：**对话与 agent 能力完全来自 AstrBot 自身**（其 LLM 工具调用循环、会话上下文、QQ 适配器），本设计要做的是把 stock_robot 的股票分析能力封装成 AstrBot 的 LLM 工具（`@filter.llm_tool`），让 AstrBot 的 agent 在需要时调用。

现有资产决定了这是一次薄接入而非重造：

- stock_robot 已是常驻 FastAPI 服务（`stock-robot run`），提供 `POST /api/v1/analyze`、`POST /api/v1/index`（结构化 JSON 并落盘报告）与报告库查询接口；
- 服务端评分、信号、五维度摘要、风险标签均为现成中文文案，插件只需做格式编排与传输。

## 目标与非目标

### 目标

1. QQ 里通过 AstrBot 的对话 agent 完成个股/指数分析；分析结果（要点摘要 + 报告链接）由插件**直接发送**到 QQ，不经过 AstrBot 的 LLM 转述，格式与内容完全可控。
2. 主仓 stock_robot 零改动。
3. 插件依赖最小（httpx），配置可改，仓库形状即 AstrBot 插件市场标准形状，为将来发布预留。

### 非目标

- 不把 stock_robot 自身的 agent（Planner/ReAct/会话管理）搬进 AstrBot；多轮对话、上下文、QQ 会话隔离全部由 AstrBot 负责。
- 本期不暴露研报检索（rag_search）与选股（screen_stocks）——主仓没有对应 HTTP 接口。
- 不做报告图片渲染、不做股票名称→代码解析（需要 6 位代码）。
- 不加固定指令处理器（如 `/分析 600519`），仅 agent 工具形态。
- 不改造主仓 CLI、依赖与打包。

## 决策记录

| 方案 | 结论 | 原因 |
|---|---|---|
| **独立插件仓 + HTTP 桥** | **采用** | AstrBot 插件硬约定"仓库根 = 插件根"，与主仓 src 多包布局冲突；重依赖（akshare/vectorbt/chromadb/langgraph）不进入 AstrBot 环境，规避包名污染与依赖冲突；HTTP 面现成，主仓零改动；独立仓天然满足发布形状 |
| 同仓适配 | 不采用 | 发布时必须拆仓；插件文件混入主仓会搅乱 lint/test/提交边界 |
| 独立仓 + 子进程桥 | 备选 | 需给主仓补机器可读入口、每次调用冷启动慢；适合将来发布给"不想常驻服务"的用户 |
| 不用插件、AstrBot 直连 MCP server | 不采用 | AstrBot 支持 MCP 工具接入，但配置体验、消息渲染、发布能力均弱于插件 |

## 架构

### 仓库与安装

新仓 `D:\code\astrbot_plugin_stock_robot`，标准 AstrBot 插件结构：

```
astrbot_plugin_stock_robot/
├── main.py              # Star 类、两个 llm_tool、插件生命周期
├── formatting.py        # 摘要文本编排（纯函数，可单测）
├── client.py            # stock_robot HTTP 客户端（含错误分类）
├── labels.py            # 展示映射表（维度/风险/指数标签，带回退）
├── metadata.yaml        # 插件元数据
├── _conf_schema.json    # WebUI 配置 schema
├── requirements.txt     # httpx
├── tests/
└── README.md
```

开发期用目录联接（junction）装进 AstrBot：

```
mklink /J "D:\code\AstrBot\data\plugins\astrbot_plugin_stock_robot" "D:\code\astrbot_plugin_stock_robot"
```

### 数据流

```
QQ 用户消息
  → AstrBot LLM（自行决定调用插件工具）
  → 插件 llm_tool handler
      1. yield 进度消息（直接到 QQ）
      2. httpx POST http://127.0.0.1:<port>/api/v1/analyze
      3. formatting 编排摘要
      4. yield 摘要消息（直接到 QQ，含报告链接）
      5. return 一句说明（进入 LLM 下轮 prompt）
  → AstrBot LLM 看到 return 内容，一句话收尾
```

插件无状态：每次调用独立、参数自带 symbol；多轮追问由 AstrBot 的 LLM 与上下文处理。

### AstrBot 契约（源码验证，本机 D:\code\AstrBot，v4.27.4）

| 事实 | 出处 |
|---|---|
| 插件根必须含 main.py + metadata.yaml；requirements.txt、_conf_schema.json 可选 | 官方插件结构约定 |
| `@filter.llm_tool(name=...)`；docstring 按 `参数名(类型): 描述` 解析为 JSON Schema；支持类型 string/number/object/array/boolean | `astrbot/core/star/register/star_handler.py:586` |
| handler 为 async 生成器时：`yield event.plain_result(文本)` → **消息直接发送给用户**（`type="tool_direct_result"`）；`return "文本"` → 作为 tool result 注入下一轮 LLM prompt；`return None` → 不注入 | `astrbot/core/astr_agent_tool_exec.py:664-703`（直发路径）、`:718-813`（返回处理） |
| 工具执行超时默认 120 秒，来源 `provider_settings.tool_call_timeout`（WebUI 可调）；超时抛异常终止该工具 | `astrbot/core/agent/run_context.py:19`、`astrbot/core/config/default.py:161` |
| 另有 background task 机制（超时 3600s，完成后唤醒主 agent 发送结果），本期不用，记录为长分析备选 | `astr_agent_tool_exec.py:159-183` |

## 详细设计

### 配置（_conf_schema.json）

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `base_url` | string | `http://127.0.0.1:25618` | 插件调用分析服务的地址 |
| `web_url` | string | 空（回退 `base_url`） | QQ 里报告链接的基址。手机访问需填局域网地址，如 `http://192.168.x.x:8765` |
| `timeout_seconds` | int | `100` | 单次分析 HTTP 超时，须小于 AstrBot 的 `tool_call_timeout` |

### analyze_stock 工具

工具签名：`analyze_stock(symbol: string)`；docstring 写明"当用户询问某只 A 股个股的分析、评价、是否值得关注/买入时使用；symbol 为 6 位股票代码（如 600519）"。

执行时序：

1. `yield event.plain_result("⏳ 正在分析 {symbol}…首次分析约需 30~90 秒，请稍等")`
2. `client.analyze_stock(symbol)` → `POST /api/v1/analyze`，超时 `timeout_seconds`
3. `formatting` 编排摘要（下方格式）
4. `yield event.plain_result(摘要)` → 直接发到 QQ
5. `return "分析结果已直接发送给用户，请勿重复输出内容，用一句话简短收尾即可"`

摘要格式（字段映射：`dimensions[dim].score` + `dimensions[dim].summary`；维度行规则：`{中文标签} {分数} — {summary}`，summary 为空时退 `score_detail`，再空退"数据不足"）：

```
📊 贵州茅台（600519）｜ 现价 1580.00 元（-1.2%）｜ 行业：白酒
综合评分 7.2/10 ｜ 操作信号：增持（建议仓位 x 成）｜ 52 周位置 42%

财务健康 7.8 — 营收同比增长 12.3%；净利润同比增长 8.1%；ROE 15.2%
技术趋势 6.5 — 站上 20 日线，MACD 金叉
估值合理 5.8 — PE-TTM 28.4，处于近 5 年 35% 分位
行业对比 7.0 — 所属行业: 白酒
舆情风险 6.2 — 近 1 日共 3 条相关新闻

⚠️ 风险：净资产收益率偏低；市盈率分位偏高

📄 完整报告：http://192.168.1.5:8765/#report-library
```

- 标题行字段：`name/symbol/overview.latest_close/overview.change_pct/overview.industry`（数值缺失时省略对应片段）
- 评分行字段：`score.final`（0-10）、`signal.label`、`signal.position`、`overview.price_position`
- 风险行：`dimensions[*].risk_flags` 汇总去重后经 `RISK_DISPLAY_NAMES` 映射，空则不显示该行
- **不含 AI 解读全文**（`commentary` 属完整报告内容）：保持消息一屏可读；若验收后觉得单薄，P1 增加"AI 解读节选"（取 `commentary` 首段）

### analyze_index 工具

工具签名：`analyze_index(symbol: string)`；仅支持单指数，docstring 写明"当用户询问大盘/指数（如上证指数、沪深 300、中证 500）走势与估值时使用"。多指数对比是 Web UI 能力，QQ 摘要不呈现（LLM 可连续调用两次）。

摘要格式（`reports[0]`）：

```
📈 沪深300（000300）｜ 2026-09-18 ｜ 最新 3985.2（+0.6%）
PE-TTM 12.4（历史分位 35%，回看 10 年）

技术面 多头 ｜ 估值面 中性 ｜ 资金面 积极 ｜ 宏观面 积极 ｜ 舆情面 中性
综合定性：<composite_comment>
建议仓位参考系数：0.6

⚠️ 风险：...（risk_list 非空时）

📄 完整报告：http://192.168.1.5:8765/#report-library
```

- 标签经 `INDEX_TAG_LABELS` 映射（10 条，未知回退原值）；`valuation_valid=false` 时附"⚠️ 估值样本不足，分位仅供参考"
- `section_macro` 为 None（不适用）时省略宏观面

### 报告链接

P0：链接固定指向报告库视图 `{web_url}/#report-library`（报告按最新在前，刚生成的报告在顶部）。

P1（待验证后升级）：若 Web UI 支持 `#report-library/<report_id>` 深链定位，则改为：`GET /api/v1/reports?type=stock&query=<代码>` 取最新一条的 id，生成深链。此项需要探针确认现行 UI 的路由能力，若需要改主仓 UI 则不做。

### 错误处理

所有分支都：先 `yield` 一条用户可读消息，再 `return` 一句给 LLM 的说明（避免 LLM 因空结果产生幻觉或重复尝试）。

| 场景 | 用户看到的消息 |
|---|---|
| 连接失败（服务未启动） | `❌ 分析服务未启动（{base_url}），请先运行 stock-robot run` |
| HTTP 422（代码非法） | `❌ 无法识别代码 {symbol}，请提供 6 位股票代码（如 600519）` |
| HTTP 500 | `❌ 分析失败：{error 摘要}` |
| 超时 | `⏱️ 分析超时（超过 {timeout_seconds} 秒）。首次分析需拉取数据较慢，可稍后重试或调大插件超时配置` |
| 响应缺关键字段/解析失败 | `❌ 分析结果格式异常，已记录日志`（同时 logger 记录完整响应） |

### 超时与性能

- 插件 HTTP 超时 `timeout_seconds`（默认 100）必须小于 AstrBot `provider_settings.tool_call_timeout`（默认 120）；README 建议用户将后者调到 ≥180。
- 首次（缓存冷）分析可能 60~90 秒：akshare 首次拉取数据。进度消息先行发送缓解等待焦虑。
- 同一次分析结论以本机服务端缓存为准；插件不做缓存。

## 映射表重复与漂移

插件拷贝三张主仓映射表：维度标签 5 条、风险标签 8 条、指数标签 10 条，与报告库 UI 的一致性是验收项。全部映射带"未知值回退原文"行为：主仓新增标签时插件优雅降级（显示代码原文），不会报错。

备选（不采用，记录）：主仓给 API 响应附加中文标签，或提供 `/api/v1/meta/labels` 端点——会让主仓 API 承担展示语义，与零改动目标冲突。

## 测试策略

1. `formatting.py` 纯函数单测：用真实 API 响应快照（个股、指数各一份）断言完整输出文本；覆盖字段缺失、维度 `status=unavailable`、风险标签为空、未知标签码回退。
2. `client.py` 单测（respx mock httpx）：200 正常、422/500 错误分类、超时、连接失败，各返回结构化错误类型。
3. 工具 handler 保持"薄包装"：只做 yield/return 编排，业务逻辑全部在可测纯函数/客户端内，单测不触碰 AstrBot 类型。
4. 手工联调验收（真实 AstrBot + 真实 stock_robot 服务 + QQ）：
   - 插件在 AstrBot WebUI 正常加载、配置可改
   - QQ 说"帮我看看贵州茅台" → 进度消息 → 摘要消息 → LLM 一句收尾
   - 摘要数字与 Web UI 报告一致
   - 手机（同一局域网）能打开报告链接
   - 停掉服务 → 收到"服务未启动"提示；无效代码 → 收到代码提示；超时 → 收到超时提示

## 待验证项（实现阶段先探针）

1. `yield event.plain_result` 直发路径在真实运行中的行为（消息到达 QQ、无重复发送、`tool_direct_result` 无副作用）——源码已确认链路，运行验证仍必须。
2. 用户 AstrBot 配置中 `provider_settings.tool_call_timeout` 实际值，以及写进 README 的建议值。
3. QQ 消息长度上限实测：摘要 + 链接是否可能超长、超长时的表现（截断/拒绝）。
4. 报告库深链能力探针（决定 P0 列表页链接是否升级为 P1 深链）。
