# AstrBot 插件接入设计（QQ 股票分析）

日期：2026-09-18
关联：新建独立仓库 `astrbot_plugin_stock_robot`（插件不在本仓实现；本仓仅做增量展示字段补充，见「主仓展示字段补充」）

## 背景

项目最初的设想是让 agent 接入 QQ。接触 AstrBot 后确定以 AstrBot 为接入载体：**对话与 agent 能力完全来自 AstrBot 自身**（其 LLM 工具调用循环、会话上下文、QQ 适配器），本设计要做的是把 stock_robot 的股票分析能力封装成 AstrBot 的 LLM 工具（`@filter.llm_tool`），让 AstrBot 的 agent 在需要时调用。

现有资产决定了这是一次薄接入而非重造：

- stock_robot 已是常驻 FastAPI 服务（`stock-robot run`），提供 `POST /api/v1/analyze`、`POST /api/v1/index`（结构化 JSON 并落盘报告）与报告库查询接口；
- 服务端评分、信号、五维度摘要、风险标签均为现成中文文案，插件只需做格式编排与传输。

## 目标与非目标

### 目标

1. QQ 里通过 AstrBot 的对话 agent 完成个股/指数分析；分析结果（要点摘要 + AI 解读全文 + 报告链接）由插件**直接发送**到 QQ，不经过 AstrBot 的 LLM 转述，格式与内容完全可控。
2. 主仓 stock_robot 不做接口开发；仅为响应增加中文展示字段（增量、不改现有字段语义）。
3. 插件依赖最小（httpx），配置可改，仓库形状即 AstrBot 插件市场标准形状，为将来发布预留。

### 非目标

- 不把 stock_robot 自身的 agent（Planner/ReAct/会话管理）搬进 AstrBot；多轮对话、上下文、QQ 会话隔离全部由 AstrBot 负责。
- 本期不暴露研报检索（rag_search）与选股（screen_stocks）——主仓没有对应 HTTP 接口。
- 不做报告图片渲染、不做股票名称→代码解析（需要 6 位代码）。
- 不加固定指令处理器（如 `/分析 600519`），仅 agent 工具形态。
- 不改造主仓 CLI、依赖与打包。

## 决策记录

| 方案 | 结论 | 原因 |
|---|---|---|
| **独立插件仓 + HTTP 桥** | **采用** | AstrBot 插件硬约定"仓库根 = 插件根"，与主仓 src 多包布局冲突；重依赖（akshare/vectorbt/chromadb/langgraph）不进入 AstrBot 环境，规避包名污染与依赖冲突；HTTP 面现成，主仓仅需增量展示字段；独立仓天然满足发布形状 |
| 同仓适配 | 不采用 | 发布时必须拆仓；插件文件混入主仓会搅乱 lint/test/提交边界 |
| 独立仓 + 子进程桥 | 备选 | 需给主仓补机器可读入口、每次调用冷启动慢；适合将来发布给"不想常驻服务"的用户 |
| 不用插件、AstrBot 直连 MCP server | 不采用 | AstrBot 支持 MCP 工具接入，但配置体验、消息渲染、发布能力均弱于插件 |

### 数据流

```
QQ 用户消息
  → AstrBot LLM（自行决定调用插件工具）
  → 插件 llm_tool handler
      1. yield 进度消息（直接到 QQ）
      2. httpx POST http://127.0.0.1:<port>/api/v1/analyze
      3. formatting 编排摘要
      4. yield 摘要消息（直接到 QQ，含报告链接）
      5. return 一句说明（进入 LLM 下轮 prompt）
  → AstrBot LLM 看到 return 内容，一句话收尾
```

插件无状态：每次调用独立、参数自带 symbol；多轮追问由 AstrBot 的 LLM 与上下文处理。

## 详细设计

### 配置（_conf_schema.json）

插件通过 `__init__(self, context: Context, config: AstrBotConfig)` 注入的 `config` 读取以下键（AstrBot 在存在 `_conf_schema.json` 时自动注入，见上表契约）。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `base_url` | string | `http://127.0.0.1:25618` | 插件调用分析服务的地址 |
| `web_url` | string | 空（回退 `base_url`） | QQ 里报告链接的基址。手机访问需填局域网地址，如 `http://192.168.x.x:8765` |
| `timeout_seconds` | int | `100` | HTTP 超时上限；运行时按超时链收敛（见「超时与性能」），非最终生效值 |

schema 版本升级时 AstrBot 自动迁移配置（补默认值、移除废弃键），发布后演进无需用户手工改配置。

### 工具注册方式

采用装饰器 `@filter.llm_tool(name=...)`。docstring 的 `Args:` 段严格按 `参数名(类型): 描述` 编写——官方文档明确警告：装饰器只解析 docstring、不读类型注解，`Args:` 缺失会让参数 schema 为空、LLM 传入的参数被静默丢弃。实现时用单测断言生成的工具 schema 非空，联调验证参数传递。备选路径（记录）：`@dataclass FunctionTool` + `context.add_llm_tools()` 可显式控制 JSON Schema（与主仓 ToolProtocol 风格一致），本期两个单参数工具用装饰器足够。

### analyze_stock 工具

工具签名：`analyze_stock(symbol: string)`；docstring 写明"当用户询问某只 A 股个股的分析、评价、是否值得关注/买入时使用；symbol 为 6 位股票代码（如 600519）"。

执行时序：

1. `yield event.plain_result("⏳ 正在分析 {symbol}…首次分析约需 30~90 秒，请稍等")`
2. `client.analyze_stock(symbol)` → `POST /api/v1/analyze`，超时 `timeout_seconds`
3. `formatting` 编排摘要（下方格式）
4. `yield event.plain_result(摘要)` → 直接发到 QQ
5. `return "分析结果已直接发送给用户，请勿重复输出内容，用一句话简短收尾即可"`

摘要格式：

```
📊 贵州茅台（600519）｜ 现价 1580.00 元（-1.2%）｜ 行业：白酒
综合评分 7.2/10 ｜ 操作信号：增持（建议仓位 x 成）｜ 52 周位置 42%

财务健康 7.8 — 营收同比增长 12.3%；净利润同比增长 8.1%；ROE 15.2%
技术趋势 6.5 — 站上 20 日线，MACD 金叉
估值合理 5.8 — PE-TTM 28.4，处于近 5 年 35% 分位
行业对比 7.0 — 所属行业: 白酒
舆情风险 6.2 — 近 1 日共 3 条相关新闻

⚠️ 风险：净资产收益率偏低；市盈率分位偏高

🤖 AI 解读
<commentary 全文（主仓 LLM 生成的四段式解读）>

📄 完整报告：http://192.168.1.5:8765/#report-library
```

- 标题行字段：`name/symbol/overview.latest_close/overview.change_pct/overview.industry`（数值缺失时省略对应片段）
- 评分行字段：`score.final`（0-10）、`signal.label`、`signal.position`、`overview.price_position`
- 维度行字段：`dimensions[dim].label`（中文名）+ `.score` + `.summary`；summary 为空时退 `score_detail`，再空退"数据不足"
- 风险行：各维度 `risk_flags_display` 汇总去重，空则不显示该行
- AI 解读段：`commentary` 全文；为空（主仓未启用 LLM）则省略整段

平台约定：aiocqhttp 适配器发送 plain 消息时会对文本首尾 `strip()`（去空格与换行）；摘要首行与末行均为内容行，不受影响，但排版不得依赖首尾空行（如需保留首尾空白可用零宽空格 `​`）。

### analyze_index 工具

工具签名：`analyze_index(symbol: string)`；仅支持单指数，docstring 写明"当用户询问大盘/指数（如上证指数、沪深 300、中证 500）走势与估值时使用"。多指数对比是 Web UI 能力，QQ 摘要不呈现（LLM 可连续调用两次）。

摘要格式（`reports[0]`）：

```
📈 沪深300（000300）｜ 2026-09-18 ｜ 最新 3985.2（+0.6%）
PE-TTM 12.4（历史分位 35%，回看 10 年）

技术面 多头 ｜ 估值面 中性 ｜ 资金面 积极 ｜ 宏观面 积极 ｜ 舆情面 中性
综合定性：<composite_comment>
建议仓位参考系数：0.6

📄 完整报告：http://192.168.1.5:8765/#report-library
```

（指数 `risk_list` 目前恒为空，不渲染风险行；若主仓未来填充则自动显示）

- 标签取 `reports[0].tag_labels`（主仓补的中文字段）；`valuation_valid=false` 时附"⚠️ 估值样本不足，分位仅供参考"
- `section_macro` 为 None（不适用）时省略宏观面
- 指数无 AI 解读概念（`composite_comment` 为规则生成的定性结论，已含在文中）

### 报告链接

P0：链接固定指向报告库视图 `{web_url}/#report-library`（报告按最新在前，刚生成的报告在顶部）。

P1（待验证后升级）：若 Web UI 支持 `#report-library/<report_id>` 深链定位，则改为：`GET /api/v1/reports?type=stock&query=<代码>` 取最新一条的 id，生成深链。此项需要探针确认现行 UI 的路由能力，若需要改主仓 UI 则不做。

### 错误处理

所有分支都：先 `yield` 一条用户可读消息，再 `return` 一句给 LLM 的说明（避免 LLM 因空结果产生幻觉或重复尝试）。

| 场景 | 用户看到的消息 |
|---|---|
| 连接失败（服务未启动） | `❌ 分析服务未启动（{base_url}），请先运行 stock-robot run` |
| HTTP 422（代码非法） | `❌ 无法识别代码 {symbol}，请提供 6 位股票代码（如 600519）` |
| HTTP 500 | `❌ 分析失败：{error 摘要}` |
| 超时 | `⏱️ 分析超时（超过 {实际生效超时} 秒）。首次分析需拉取数据较慢，可稍后重试或调大插件超时配置` |
| 响应缺关键字段/解析失败 | `❌ 分析结果格式异常，已记录日志`（同时 logger 记录完整响应） |

### 超时与性能（超时链一致性）

超时链分两层，**插件必须始终先于 AstrBot 超时**——AstrBot 超时会直接终止工具，用户只能看到通用错误，不会收到插件的友好提示：

1. AstrBot 工具超时：`provider_settings.tool_call_timeout`（默认 120 秒）。
2. 插件 HTTP 超时：配置 `timeout_seconds`（默认 100 秒），**运行时自动收敛**——每次调用读取 AstrBot 配置（`self.context.get_config(umo=event.unified_msg_origin)` → `provider_settings.tool_call_timeout`），实际生效值 = `min(配置值, tool_call_timeout − 15)`；15 秒边际覆盖格式化与消息发送耗时。读取失败则回退配置值并 `logger.warning`。

进度消息与超时错误消息均写出本次实际生效的超时值，便于排查。README 说明该链条，建议 `tool_call_timeout ≥ 120`。

- 首次（缓存冷）分析可能 60~90 秒：akshare 首次拉取数据。进度消息先行发送缓解等待焦虑。
- 同一次分析结论以本机服务端缓存为准；插件不做缓存。

## 主仓展示字段补充

分析服务响应中的部分字段是内部代码（维度码、风险标签码、指数标签码），QQ 摘要需要中文展示。为保证单一事实源、避免两处维护漂移，由主仓在响应中**增量**补充已映射的中文字段，不改动任何现有字段，Web UI 与既有测试不受影响：

| 端点 | 增量字段 | 取值来源 |
|---|---|---|
| `POST /api/v1/analyze` | `dimensions[dim].label`（"财务健康"等 5 条） | 复用主仓维度中文映射（`src/core/pipeline.py` 现有 `dim_labels`） |
| `POST /api/v1/analyze` | `dimensions[dim].risk_flags_display`（"净资产收益率偏低"等 8 条） | 复用 `risk_display_name()`（`src/report/formatter.py:88`） |
| `POST /api/v1/index` | `reports[i].tag_labels`（`{技术面: 多头, 估值面: 中性, ...}` 10 条值域） | 复用 `INDEX_TAG_LABELS`（`src/index/enricher.py:4`） |

主仓测试：在 `tests/api/test_app.py` 补断言（新字段存在、映射正确），运行 `tests/api/` 确认无回归。

## 测试策略

1. `formatting.py` 纯函数单测：用真实 API 响应快照（个股、指数各一份）断言完整输出文本；覆盖字段缺失、维度 `status=unavailable`、风险标签为空、`commentary` 为空（省略 AI 解读段）。
