# 数据源退化修复设计

日期：2026-08-23
状态：已批准

## 一、背景与问题

`stock-robot analyze 000001` 报告出现大量"数据不足"：估值、行业、所属行业全部缺失，财务资产负债率缺失，公告获取失败。经系统排查（探针实测 + 缓存 DB 扫描），根因如下：

### 根因链

1. **雪球接口全挂（核心）**：akshare 1.18.81 的雪球接口强制要求 `xq_a_token` 登录凭证，上游返回 400016。影响：
   - `get_individual_info()` 返回空 → 行业分类失败 → 行业对比维度数据不足
   - `_fetch_valuation` 主路径（雪球 spot）→ PE/PB 全空
   - 总股本（`reg_asset`）拿不到 → 估值序列 0 个点 → 估值维度数据不足
2. **东财推送分站被代理阻断**：`17.push2.eastmoney.com`（行业列表）、`82.push2.eastmoney.com`（全市场 spot）稳定 ProxyError，行业/估值回退路径全断；主域 `push2.eastmoney.com` 间歇性失败
3. **缓存毒化（设计缺陷放大器）**：`_set_cache` 无条件写缓存，失败/退化结果（财务 equity 全 None、行业"未知"）被缓存 7 天。缓存 DB 实测 10 条中 5 条退化（000001 与 600519 均受影响），坏数据从 08-15 持续至今
4. **同类退化点**：
   - `_fetch_industry` 回退取全市场第一个板块名（`names[0]`），接口恢复后会张冠李戴
   - `_ak_individual_info_em`（东财轻量接口，含行业/总股本字段）定义了但从未被调用
   - `retry_on_network_error` 不认 akshare APIError，400016 不重试直接吞
   - 公告用全市场接口拉取再过滤（`stock_notice_report(symbol="全部")`），偶发 KeyError('代码')，且当日全市场公告为空时拿不到个股公告
   - LLM 舆情标注失败时 `json.loads` 对 fallback 文案报"Expecting value"（噪音日志）

### 已排除项

- 指数数据源（funddb/csindex）不受影响
- 腾讯行情、同花顺财务、legulegu、东财新闻接口稳定可用

## 二、目标与非目标

### 目标

1. 每类数据具备 ≥2 个真实可用的异构数据源，在线源优先、链式回退
2. 持久缓存只存健康数据，退化结果不落地
3. 源头故障时内存断路器防重复轰炸，恢复后自动复位（自愈）
4. 估值推导结果与在线实测源交叉校验，偏差大时自动锚定修正，防止报告给出错误数据
5. 全修同类退化点（names[0]、公告接口、LLM 标注噪音、APIError 重试）

### 非目标

- 指数/海外数据源改造（已确认无同类问题）
- 配置雪球 token（彻底移除雪球依赖）
- 引入数据源健康抽象层（当前规模下过度设计）

## 三、架构决策（已确认）

| 决策点 | 结论 |
|---|---|
| 修复范围 | 核心三件套 + 同类退化全修 |
| 雪球处置 | 彻底移除，换用东财/腾讯/同花顺/legulegu/本地表 |
| 缓存策略 | 持久层只存健康数据；失败结果不落库；内存断路器 |
| 行业映射表 | 修复错误条目（000001→银行）+ 扩充 |
| 链优先级 | 在线源优先，离线兜底（财报反推、本地表）垫底 |
| 估值校验 | 实测锚定（cross-validated anchoring），不是标记告警 |

## 四、组件设计

### 组件 1：数据源链改造（src/data/akshare.py + src/data/enrichers/*）

#### 1.1 行业判定（_fetch_industry 重构）

```
行业名 = 东财轻量接口 stock_individual_info_em（在线，间歇失败）
       → 本地映射表 industry_mapping.csv（离线，永远可用）
成分股 = legulegu 申万成分股（在线，已验证可用）
       → 东财行业成分股 stock_board_industry_cons_em（在线，push2 间歇）
删除：雪球 stock_individual_basic_info_xq、_ak_industry_name（17.push2）、names[0] 逻辑
```

#### 1.2 总股本（新增 get_total_shares()）

```
总股本 = 东财轻量接口"总股本"字段（在线，间歇失败）
       → 腾讯行情 stock_zh_a_daily outstanding_share 流通股本（在线，已验证）
       → 财报反推 net_profit ÷ basic_eps（离线兜底，零请求）
```

财报反推口径约束：取最近一期**累计**净利润 ÷ 同期累计 EPS，禁止单季/累计混用（单测防错）。

#### 1.3 财务（_fetch_financial 资产负债表补充链）

```
equity/assets = THS 旧表 stock_financial_debt_ths（现有）
              → THS 新长表 stock_financial_debt_new_ths（长表格式，需新解析器）
              → 空（记录缺失，不阻断利润表数据）
```

新长表解析器：`report_date / metric_name / value` 结构，按 metric_name 匹配"资产合计/所有者权益"类目。

#### 1.4 新闻/公告（_fetch_news 重构）

```
新闻 = stock_news_em（在线，现有）
公告 = stock_individual_notice_report(security=个股)（在线，已验证，替代全市场拉取过滤）
公告接口失败 → 仅新闻，不报错
```

#### 1.5 估值（移除雪球/spot_em 使用点）

- `_fetch_valuation` 移除雪球 spot 与 82.push2 spot_em
- `ValuationEnricher._get_total_shares` 迁移到 `get_total_shares()` 三级链
- `industry_enricher._fetch_peer_valuation` 雪球补查删除——legulegu 成分股自带 PE/PB，缺失留 None（行业中位数现有容错已覆盖）

#### 1.6 行情（保持现状）

price 链为现有 腾讯 `stock_zh_a_daily` → 东财 `stock_zh_a_hist`，实测可用，不改动。

### 组件 2：健康校验 + 内存断路器（src/core/pipeline.py）

```
fetch 流程（每 symbol+data_type）：
  读持久缓存 ──命中且健康──▶ 直接使用
       │ 未命中
       ▼
  断路器闭合？ ──否（打开中）──▶ 直接返回空（"数据源暂不可用"，10 分钟后再试）
       │ 是
       ▼
  链式采集（主源→备源→...）
       │
  成功且健康 ──▶ 写持久缓存 + 断路器复位
  全链失败/退化 ──▶ 不写缓存 + 断路器计数（连续 3 次 → 打开 10 分钟）
```

- 健康判据 `_is_healthy(data_type, data)`：空列表、industry="未知"、financial 12 期 equity 全 None、price < 60 条 → 退化不落库
- 断路器状态：Pipeline 实例内存，per (symbol, data_type)，进程重启即清零
- `retry.py`：`NETWORK_ERRORS` 补入 akshare APIError（网络类可重试；400016 类业务错误不重试，避免浪费时间——雪球移除后该错误面已消失）

### 组件 3：估值交叉校验 — 实测锚定（src/data/enrichers/valuation_enricher.py）

```
校验源 = 腾讯快照 qt.gtimg.cn（在线，已验证，独立口径）→ 新浪快照 hq.sinajs.cn（备选）→ 无校验源

实测 PE 可得时：
  shares_anchor = 实测PE × TTM净利润 ÷ 现价        ← 反推总股本锚点
  历史 PE 序列 = shares_anchor × 历史价格 ÷ TTM净利润
  历史 PB 序列 = shares_anchor × 历史价格 ÷ 最新净资产
  三级链估算值 vs 锚定值 偏差 >15% → 告警日志（提示估算链退化），结果一律用锚定值
  实测 PB 直接作为当前点展示值（资产负债表缺失时也能展示）

实测不可得（腾讯/新浪均挂）：
  用三级链估算值，序列标注"未经实测校验"
```

边界：TTM 净利润错误无法交叉校验（THS 为唯一财务源）；东财财务接口当前环境不可用，留作代码级备用（环境恢复自动启用，非本次范围）。

### 组件 4：同类退化点全修

1. 行业映射表：修复 000001→银行（含 style_category 对齐同类银行股），扫描其他错误条目
2. LLM 舆情标注：`generate()` 返回 fallback 文案（以"（LLM"开头）或空时直接跳过标注，不进入 `json.loads`
3. 公告接口：改用个股接口后，全市场接口及 KeyError 暴露面移除

## 五、数据流（一次 analyze 000001）

```
① price:     腾讯 ✅ → 写缓存
② financial: THS 利润表 ✅ → 资产负债表链（debt_ths → debt_new_ths）→ 写缓存
③ valuation: 总股本链（东财→腾讯→财报反推）→ 推导序列 → 腾讯快照实测锚定 → 写缓存
④ industry:  行业名链（东财→本地表"银行"）→ legulegu 成分股（带 PE/PB）→ 写缓存
⑤ news:      东财新闻 ✅ + 个股公告 ✅ → 写缓存
⑥ 充实器 + 分析器 + LLM 解读 → 报告
```

任一链全挂：该维度"数据不足"（标注失败链），不影响其他维度。

## 六、错误处理

| 场景 | 行为 |
|---|---|
| 链中单源失败 | logger.warning + 切下一源，不中断 |
| 全链失败 | 返回空 → 维度"数据不足" → 断路器计数+1 |
| 断路器打开中 | 跳过源头请求直接返回空，10 分钟后自动试探 |
| 推导 vs 实测偏差 >15% | 告警日志，结果用锚定值（正确性不受影响） |
| 缓存命中但退化 | 健康校验拦截，走采集链 |
| LLM 标注失败 | 识别 fallback 文案跳过，规则兜底 |

## 七、测试计划

### 单测

- 总股本三级链：mock 各源失败/成功，断言切换顺序（在线优先）
- 财报反推：单季/累计混合数据传入，断言正确口径
- 行业判定：东财失败 → 本地表兜底；本地表缺失 → 空
- 健康校验：退化数据不写缓存
- 断路器：3 次失败 → 打开 → 成功复位；打开期间断言 mock 调用次数为 0
- 实测锚定：偏差 10% / 20% 两档，断言锚定值与告警行为
- THS 新长表解析器：格式转换正确

### 集成

pipeline 完整 analyze 流程（mock 数据源），断言各维度充足性 + 缓存内容健康。

## 九、风险与边界

- 东财主域间歇失败：由本地表/财报反推兜底，行业/总股本不中断；环境恢复后自动启用在线源
- TTM 净利润无第二数据源校验：承认边界，THS 数据错误时锚定值同步错误（影响面：估值数值精度，不涉及维度充足性）
- legulegu 为第三方网页爬虫，结构变化风险：失败时降级到东财行业成分股，再降级到"无成分股"（行业名仍展示，行业对比维度数据不足）
