# 会话可读性与标题归纳改造设计

## 目标

改善投研工作台会话页的首屏密度与消息可读性：建议栏仅服务于空会话；所有自动标题具备辨识度；模型正文、推理和历史异常格式均能稳定展示。

## 用户体验

### 建议栏

- 新建且没有用户消息的会话显示四张两列建议卡，留出足够间距。
- 当前会话一旦存在用户消息，建议栏立即隐藏，不随流式运行状态重新出现。
- 清空当前会话后，建议栏重新出现。

### 标题

- 自动标题优先依据第一条用户消息生成。
- 若第一条只能生成通用/低信息量标题，则读取第二条用户消息并以两条内容共同归纳标题。
- 旧会话在加载会话列表时补齐或优化自动标题；手动标题保持不变。
- 标题生成失败时使用确定性本地回退标题，绝不显示空标题或原始长消息。

### 助手消息

- 服务端把内容块解析为 `text`（正文）和 `thinking`（推理）两个字段。
- 正文作为 Markdown 安全渲染，支持标题、表格、列表、代码、强调、链接与换行。
- 推理默认折叠为“查看分析过程”；没有推理时不渲染该控件。
- 原先已持久化为 Python 列表或 JSON 内容块的助手消息，读取时兼容解析；解析失败时作为普通文本安全展示。

## 架构与数据流

1. 标题服务为会话管理层提供“从前两条用户消息归纳标题”的纯函数，并区分自动、手动与历史来源。
2. 会话列表/详情读取时，识别可回填的自动标题，异步或受控地更新持久化记录，避免覆盖手动标题。
3. Agent 与普通聊天的模型响应都经过共享内容规范化器：从字符串、JSON 内容块或 Python 表示的内容块中抽取正文与推理。
4. 新消息持久化为可读取的正文；需要保留的推理以明确的结构化表示关联消息，避免污染 Memory 上下文。
5. 前端按消息类型渲染正文和折叠推理，并依据当前会话是否有用户消息切换建议栏。

## 兼容与边界

- 不进行破坏性数据库迁移；新增字段/元数据采用可选方式并兼容旧 `messages` 行。
- 历史内容块支持 Python 字面量和 JSON；只接受预期字段，禁止执行任意表达式。
- 不信任的正文仍经现有安全 Markdown 转义处理，链接仅允许 HTTP(S)/mailto。
- SSE 中的最终正文和推理分开发送，前端在流结束后刷新会话详情以保证持久化一致。

## 验证

- 标题：首条成功、首条不足且第二条补足、历史回填、手动标题保护。
- 内容规范化：字符串、OpenAI/Anthropic 内容块、Python/JSON 历史字符串、异常输入。
- API：流式聊天事件包含规范化正文/推理，历史会话详情可正确返回。
- 前端单元/静态检查：建议栏显示条件、Markdown 渲染与折叠推理的 DOM 行为。
