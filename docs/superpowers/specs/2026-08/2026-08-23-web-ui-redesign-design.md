# Stock Robot Web 前端重设计

## 背景

当前 Web 前端存在三个主要问题：

1. 会话标题直接截取第一条用户消息前 20 个字符，缺少主题辨识力，也不便于管理长期研究会话。
2. 聊天产生的结构化分析结果只在当前响应中短暂存在，历史消息恢复后无法重新打开完整报告；纯文本报告的 Markdown 展示能力也不足。
3. 顶部入口、左侧会话、功能导航和内容区域的层级不清晰，报告阅读空间、聊天输入区及移动端布局均需要重新组织。

本次改造采用“研究工作台”作为整体框架，吸收沉浸式报告的阅读体验，并将结构化报告作为对话中的持久研究成果。

## 目标

- 建立稳定清晰的三段式应用外壳：左侧导航与会话、中间工作区、按需展开的右侧报告抽屉。
- 为会话生成简洁、有辨识力且可手动修改的标题。
- 在聊天中展示报告摘要卡，并通过右侧抽屉阅读完整结构化报告。
- 让报告在切换会话或刷新页面后仍可恢复。
- 统一独立报告页与聊天报告抽屉的渲染逻辑。
- 提升 Markdown、安全性、响应式布局和整体视觉层级。

## 非目标

- 不引入 React、Vue、前端构建工具或新的部署链路。
- 不重写分析管道或调整已有评分算法。
- 不在本次改造中增加协同编辑、分享链接或复杂报告版本管理。
- 不为已有纯文本历史消息批量重新生成结构化报告。

## 整体体验

### 应用外壳

桌面端由三个区域组成：

- 左侧固定工作台：产品标识、新建会话、智能会话列表以及聊天、个股报告、指数分析、订阅推送等功能导航。
- 中间主工作区：根据当前功能显示聊天、独立报告、指数分析或订阅管理。
- 右侧报告抽屉：只在用户查看聊天中的报告成果时出现，默认约占可用宽度的 45%，并使中间聊天区域平滑收窄。

顶栏不再并排放置个股和指数两个输入组。顶栏只保留当前页面标题、全局股票搜索和必要操作；指数分析等入口归入左侧导航对应页面。

### 会话列表

每个会话项显示：

- 智能标题；
- 可识别时显示相关股票名称或代码；
- 相对更新时间；
- 当前会话的明确选中状态。

重命名和删除收进会话项的操作菜单，不再常驻显示删除符号。用户手动修改标题后，自动标题流程不得覆盖该标题。

### 聊天

空会话显示简洁的产品说明和常用研究建议。消息区明确区分用户、助手、执行进度和研究成果。输入区支持多行内容，并在聊天区域底部保持稳定位置，不遮挡消息。

分析任务完成后，聊天中显示报告摘要卡，包含标的、综合评分、核心结论、主要风险和生成时间。用户点击摘要卡或“查看完整报告”按钮后，右侧报告抽屉打开；聊天不会跳转到其他页面，滚动位置保持不变。

### 报告抽屉

抽屉内容按专业研报结构组织：

1. 股票名称、代码、行情变化、行业与更新时间；
2. 投资摘要与综合评分；
3. 财务健康；
4. 技术趋势；
5. 估值分析；
6. 行业对比；
7. 舆情风险；
8. 风险提示；
9. AI 解读。

抽屉顶部提供关闭和刷新操作，并提供章节导航。结构化字段使用专用组件展示，AI 解读和其他自然语言内容使用 Markdown 渲染。切换不同报告时复用同一个抽屉实例。

独立“个股报告”页面继续保留，用于直接输入股票代码发起分析，并复用相同的报告渲染器。

## 会话标题设计

标题采用“双阶段生成”。

### 第一阶段：本地规则标题

首次发送消息后立即生成，不增加网络调用。规则提取以下信息：

- A 股代码、指数代码及已知股票名称；
- 比较、估值、财务、技术、行业、风险、择时等研究意图；
- 一个或多个主要标的。

标题目标长度为 8 至 20 个汉字或等价字符。例如：

- `分析一下600519近期估值和趋势` → `贵州茅台估值与趋势`
- `比较沪深300和中证红利` → `沪深300与中证红利比较`

无法可靠识别时，对首条消息做去口语化和安全截断，而不是原样取前 20 个字符。

### 第二阶段：LLM 异步润色

首轮回复完成后，后台使用现有模型把本地标题润色为简洁研究主题。该调用不得阻塞聊天完成事件。生成结果必须满足长度、非空、无换行等约束，否则丢弃。

模型未配置、调用超时或异常时保留本地标题。已手动重命名的会话跳过自动润色。

### 数据与接口

`sessions` 增加标题来源或锁定状态，用于区分默认、本地生成、LLM 生成和手动标题。数据库迁移采用向后兼容的增量方式。

增加会话重命名接口。会话列表响应继续返回标题，并增加展示所需的更新时间、相关标的等可选元数据。接口层负责校验标题长度与空值。

## 报告成果持久化

### 问题

当前会话只持久化 `role` 和 `content`。SSE 响应中的结构化工具结果不会随历史消息恢复，因此刷新或切换会话后无法重建报告摘要卡及完整报告。

### 数据模型

新增会话成果表，至少包含：

- 成果 ID；
- 会话 ID；
- 关联消息 ID 或稳定的消息关联标识；
- 成果类型；
- 标的代码；
- 结构化 JSON；
- 创建与更新时间。

首期成果类型只要求支持个股报告，但模型允许后续扩展指数报告等类型。删除会话时级联删除成果；清空会话时同步清空成果。

### 写入流程

分析执行成功并得到完整个股报告 JSON 后：

1. 正常向聊天 SSE 推送执行进度和最终摘要；
2. 将结构化报告保存为会话成果；
3. 在完成事件中返回成果摘要和成果 ID；
4. 前端立即渲染摘要卡并允许打开抽屉。

报告持久化失败时，不把整轮聊天标记为失败；前端仍可展示本轮内存数据，同时提示该报告可能无法在刷新后恢复，服务端记录错误日志。

### 读取流程

历史消息接口返回消息及其关联成果，或提供等价的会话详情响应。前端恢复会话时，根据成果类型渲染报告摘要卡。打开抽屉时优先使用当前缓存；缓存不存在时按成果 ID 获取完整 JSON。

已有历史会话若只有纯文本报告，则显示普通助手消息，并使用增强后的 Markdown 渲染器，不尝试反向解析成结构化 JSON。

## 前端模块拆分

保持原生 ES Module 架构，按职责拆分：

- 应用外壳：处理三栏布局、导航折叠、抽屉状态和响应式行为。
- 会话列表：负责标题、元数据、选中状态、重命名及删除菜单。
- 聊天视图：负责消息、空状态、输入区、执行进度和报告摘要卡。
- 报告渲染器：将结构化报告 JSON 转成统一章节，供独立报告页和抽屉共用。
- 报告抽屉：负责打开、关闭、报告切换、章节定位与刷新。
- Markdown 渲染器：在先转义不可信输入的前提下支持标题、段落、有序和无序列表、引用、表格、围栏代码、行内代码、强调与安全链接。
- 设计令牌：集中定义颜色、字号、间距、圆角、阴影和响应式断点。

组件之间通过明确的数据对象和应用事件通信，避免由 DOM 文本反向推断业务状态。

## 视觉设计

整体风格为克制、专业的投研工作台：

- 左侧使用深蓝灰背景，突出导航稳定性；
- 主内容使用浅色阅读画布；
- 上涨、下跌、风险和中性状态使用低饱和且有文字辅助的状态色；
- 减少重复卡片边框和大块空白，以排版、间距和浅层表面区分章节；
- 报告正文采用更舒适的阅读宽度、字号和行距；
- 数值、结论、风险及章节标题形成清晰的视觉层级。

交互控件提供悬停、焦点、禁用和加载状态；不得只用颜色表达状态。

## 响应式行为

- 宽桌面：完整左侧栏、中间工作区和约 45% 宽的报告抽屉。
- 中等宽度：左侧栏收窄，报告抽屉可适当增宽以保证正文可读性。
- 小屏：左侧栏变为可呼出的导航层；报告抽屉变成全屏覆盖层；关闭后回到原聊天位置。
- 长标题、宽表格和长代码块不得撑破页面。报告表格允许在自身容器内横向滚动。

## 状态与异常处理

- 标题生成失败不影响聊天，保留本地规则标题。
- 报告加载失败时，抽屉显示局部错误与重试操作，不清空聊天内容。
- 刷新报告时保留旧内容，成功后原位替换；失败则继续显示旧版本并提示刷新失败。
- 切换会话时关闭不属于新会话的报告抽屉。
- 并发打开或刷新报告使用请求令牌，迟到响应不得覆盖当前报告。
- 网络断开状态在应用外壳中统一提示，并避免重复弹窗。

## 测试与验收

### 后端

- 本地标题器覆盖代码、股票名称、比较型和无法识别输入。
- LLM 润色覆盖成功、无效结果、超时、异常及模型未配置降级。
- 手动标题不会被自动覆盖。
- 会话成果可写入、读取、更新，并随清空或删除会话移除。
- API 覆盖会话重命名、成果读取、历史恢复及错误校验。

### 前端

- Markdown 渲染覆盖新增语法与 XSS、危险链接等安全用例。
- 报告摘要卡和完整章节对缺失字段具有稳定降级。
- 抽屉打开、关闭、切换、刷新和迟到响应处理正确。
- 会话切换与页面刷新后能恢复报告成果。

### 浏览器验收

- 在桌面、中等宽度和移动端检查应用外壳。
- 检查长会话标题、长 Markdown 表格、长代码块、空报告和多个报告切换。
- 检查键盘焦点、关闭操作、章节定位及滚动位置保持。
- 检查模型未配置、接口失败和网络中断状态。

日常修复循环只运行改动文件的 Ruff、Pyright 和定向 pytest。核心链路完成后，根据用户要求和项目约定决定是否执行全量检查。

## 兼容与迁移

SQLite 迁移必须保留现有会话和消息。新增列提供安全默认值，新成果表不要求回填旧数据。现有 REST 路径尽量保持兼容；新增字段均为向后兼容扩展。前端部署仍由 FastAPI 静态文件服务完成，不增加构建产物。

## 成功标准

- 会话列表不再直接显示首条用户消息截断文本，并允许用户重命名。
- 首轮分析完成后，会话标题能在不阻塞聊天的情况下得到更准确的主题名称。
- 聊天报告以摘要卡出现，点击后在右侧抽屉展示完整结构化内容。
- 刷新页面或切换会话后，已保存报告仍可重新打开。
- 独立报告页与报告抽屉使用同一套结构化渲染逻辑。
- 桌面和移动端均不存在主要内容遮挡、不可关闭抽屉或页面级横向溢出。
