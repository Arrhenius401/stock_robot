# 单股报告信号回测设计

日期：2026-08-29

## 目标

为 Stock Robot 增加面向个人开发者的本地回测能力，用于验证单只 A 股的报告信号在指定历史区间内的表现。第一期由 CLI 发起，采用 VectorBT 社区版和现有 AkShare 日线数据，不接入商业回测平台。

本功能用于研究与复现，不构成投资建议或未来收益承诺。

## 第一期开闭范围

### 做

- 单只 A 股日线回测。
- CLI 命令发起：股票、日期区间、策略、基准均可指定。
- 报告技术信号的历史重算：技术评分映射为 `attack`、`watch`、`defend`。
- 按目标仓位调仓：默认 `70%`、`40%`、`0%`。
- 当日收盘计算信号，下一交易日开盘成交。
- YAML 策略实体、YAML 默认成本参数和可复现运行快照。
- 输出收益、最大回撤、夏普、交易次数、逐日净值、交易记录和相对基准表现。

### 不做

- 多股票股票池、选股、组合优化与行业轮动。
- 分钟级或 tick 级回测。
- 实盘、模拟盘或第三方商业平台 API 集成。
- 使用当前时点的财务、估值、行业、新闻或 LLM 结果回放到历史。
- 对免费公共数据的商业级完整性作保证。

## 技术选择与边界

使用 VectorBT 社区版完成本地组合仿真和绩效统计，行情继续由 AkShare 获取。项目负责把自身信号规则转换为标准化的目标仓位序列，并负责 A 股默认成本、数据校验、产物保存和结果解释。

本期只消费可从历史价格严格重算的技术面输入。综合评分中的实时估值、最近财务数据、行业横截面和新闻不可用于本期历史回测，避免未来函数。

## CLI 流程

目标命令形态：

```text
stock-robot backtest 000001 --strategy report_technical --start 2022-01-01 --end 2025-12-31
```

可选参数至少包括：

- `--strategy`：策略 ID；未传时使用全局默认策略。
- `--start`、`--end`：回测区间。
- `--benchmark`：覆盖全局默认基准。
- 成本相关参数允许覆盖 YAML 默认值，但日常运行不要求逐项传入。

执行步骤：

1. 校验股票、日期、策略和基准。
2. 读取策略并获取回测区间前的预热日线；默认预热期为 90 个交易日，确保 MA60、MACD 等指标在首个回测日可用。
3. 逐个交易日仅使用当日及以前的数据计算技术评分和信号。
4. 把信号转换为目标仓位，在下一交易日开盘模拟成交；应用佣金、印花税和滑点。
5. 计算策略与基准的净值、收益和风险指标，保存完整运行产物。
6. 在 CLI 输出精简摘要与报告路径。

## 策略实体

策略是独立于 CLI 和回测引擎的 Pydantic 实体，以 YAML 文件定义。第一期采用配置型策略；复杂 Python 插件推迟到后续需要时再引入。

示例：

```yaml
id: report_technical
name: 报告技术信号策略
version: 1
signal_source: technical_score
thresholds:
  attack: 7
  watch: 4
target_positions:
  attack: 0.7
  watch: 0.4
  defend: 0.0
execution: next_open
warmup_days: 90
cost_profile: a_share_default
```

策略 ID 是稳定、可读、项目内唯一的人工标识，只允许小写字母、数字和下划线。加载全部策略 YAML 时，重复 ID 必须报错。策略有实质变更时由维护者递增 `version`。

系统额外对标准化后的完整策略配置计算短哈希。版本用于人类理解，哈希和运行快照才是复现事实；即使维护者遗漏版本递增，历史运行仍可辨认实际参数差异。

## 配置组织

策略文件不与全局运行配置混放：

```text
.stock_robot/config.yaml
config/strategies/report_technical.yaml
```

全局配置保存默认选择与公共运行假设：

```yaml
backtest:
  default_strategy: report_technical
  default_benchmark: money_fund
  cost_profiles:
    a_share_default: {}
  benchmarks:
    money_fund:
      name: 中证货币型基金指数
      symbol: H11025
    csi_300:
      name: 沪深300
      symbol: "000300"
    csi_all_bond:
      name: 中证全债指数
      symbol: H11001
```

默认基准为中证货币型基金指数；沪深 300 和中证全债为可选基准。CLI 的 `--benchmark` 优先于全局配置。数据源无法提供某个基准时必须明确失败，不能以零收益代替。

## 输出目录与产物契约

运行产物统一保存到现有 `reports/` 根目录：

```text
reports/
├─ stock/<股票代码>/<YYYY-MM>/...
├─ index/<指数代码>/<YYYY-MM>/...
└─ backtests/<策略ID>/<股票代码>/<YYYY-MM>/<运行ID>/
```

其中运行 ID 为 `<YYYYMMDD_HHMMSS>_v<version>_<策略配置短哈希>`，例如：

```text
reports/backtests/report_technical/000001/2026-08/
└─ 20260829_103000_v1_a13c9b2f/
```

每次成功运行写入以下文件：

- `report.md`：面向人的完整回测说明与指标。
- `summary.json`：稳定的机器可读摘要，供以后 API 或 Web UI 使用。
- `equity_curve.csv`：每日策略和基准净值、目标/实际仓位、信号。
- `trades.csv`：每笔调仓的时间、方向、数量、成交价、费用和原因。
- `manifest.json`：股票、日期、数据范围、策略完整快照、成本、基准、警告和实现版本。

股票分析报告只写入 `reports/stock/`，指数分析报告只写入 `reports/index/`。已有旧目录下的历史报告不自动迁移。

## 失败处理

- 非法股票代码、日期区间、策略 ID 或基准 ID：执行前退出，不创建结果目录。
- 预热期或回测区间所需的股票数据不足：明确失败并给出原因。
- 股票或基准关键行情获取失败：本次运行失败，不产生伪造的成功指标。
- 非关键数据缺失可以产生 warning；无法连续计算净值时必须终止。
- 只有完整产物写入成功后，运行目录才被视为成功结果。

## 测试与验收

测试不依赖网络，使用固定 OHLCV 夹具。

- 策略 YAML 的字段、重复 ID、阈值、仓位和成本引用校验。
- 三档信号到目标仓位的映射。
- 当日信号、下一交易日开盘成交的时序，确保不存在未来函数。
- 佣金、印花税、滑点、现金和持仓计算。
- 货币基金、沪深 300、中证全债基准选择与 CLI 覆盖。
- 完整目录布局与五类结果文件内容。
- 数据不足、基准失败、非法参数和部分缺失数据的错误/警告路径。

CLI 验收至少执行一次固定数据的单股回测，并确认终端摘要与 `report.md`、`summary.json`、`equity_curve.csv`、`trades.csv`、`manifest.json` 一致。
