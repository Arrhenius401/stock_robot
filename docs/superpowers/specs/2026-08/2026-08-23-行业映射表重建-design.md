# 行业映射表重建设计

## 背景与问题

`data/industry_mapping.csv` 共 5534 只 A 股，其中 5514 只为"综合/高端制造"占位，仅 20 只银行股手工修复。

**根因**：`scripts/generate_industry_mapping.py` 使用 `ak.stock_info_a_code_name()` 拉取全量 A 股列表——该接口只有 code+name 两列，无 industry 列，导致 `row.get("industry", "")` 恒为空 → 全部落为占位。

**影响是实质性的**：行业信息直接驱动打分体系：

- `pipeline.py:152` 将映射表一级行业填入 `ctx.sw_industry`
- `config_loader.load(sw_industry)` 按**申万一级名**加载打分配置（`override/银行.yaml` 等专属权重）并经 `申万_大类_映射.yaml` 映射到 8 大风格大类
- 大类决定 scorer 策略：银行走 BankScorer（PB 优先、PE 不适用）、周期资源走 CyclicalScorer（PE 反转）、医药/地产/非银/科技各有专属规则
- 全占位导致所有股票走 `综合→高端制造→GeneralScorer`——银行股没有用 PB 估值逻辑打分、周期股没有 PE 反转，**这是投资建议层面的错误**

消费方汇总：

| 消费方 | 使用字段 | 影响 |
|---|---|---|
| `config_loader` / scorer 策略选择 | sw_level1 → style_category | 打分权重与策略（核心） |
| 报告行业展示 | sw_industry | 展示 |
| agent 行业筛选工具（pipeline_tools.py:314） | sw_level1 / sw_level2 | 选股功能（二级是增强） |
| 东财行业失败兜底（akshare.py:87） | sw_level1 | 行业归属兜底 |

三级行业无任何消费方，仅作为推导一/二级的中间数据层。

## 精度目标

- **一级行业（sw_level1）100% 准确**——是打分配置的键
- **二级行业（sw_level2）真实填充**——agent 选股有真实需求
- **三级行业不落盘**——仅重建时用于推导
- 口径：**申万官方分类**（非东财行业名，东财与申万一级并非一一对应）

## 数据源方案（已探针验证）

选定 **legulegu 直连抓取**。排除方案：
- akshare `sw_index_first_info` 可用但 `sw_index_third_cons` 有 `ValueError: Length mismatch` bug，且其内部同样拉 legulegu，绕远路
- 东财行业（`stock_board_industry_cons_em` 86 板块）非申万口径，二级缺失

### 探针确认的事实（2026-08-23 实测）

1. **行业总览页**：`https://legulegu.com/stockdata/sw-industry-overview/`（**必须带尾部斜杠**；无斜杠返回不同页面）。旧版 `level1Items` 等 JS 变量已不存在，新版为纯 HTML 渲染。
   - 平铺 497 个容器：`<div id="801983.SI" class="lg-industries-item">`
   - 名称标记：`<div class="lg-industries-item-number">种植业(20)<span class="parent-industry-name">[农林牧渔]</span></div>`
   - **一级行业无 parent span**；二级/三级带 parent span，值为**直接父级名**
   - 计数验证：497 = 31 一级 + 131 二级 + 335 三级
   - 层级链验证：种子(850111.SI) parent=种植业，种植业(801015.SI) parent=农林牧渔
2. **成分股页**：`https://legulegu.com/stockdata/index-composition?industryCode={代码}`，表格 `#tableID`，每行含：股票代码（`/s/600097` 链接）、简称、纳入时间、**申万2级列**、细分概念（骨架屏动态加载，忽略）
3. **个股页**（单只反查入口）：`https://legulegu.com/s/{symbol}` 行业区块 `<span class="industry">`：
   ```html
   <a class="industry-name" href="...industryCode=801010.SI">I农林牧渔</a>
   <i class="fa fa-angle-right arrow"></i>
   <a class="industry-name" href="...industryCode=801015.SI">II渔业</a>
   <i class="fa fa-angle-right arrow"></i>
   <a class="industry-name" href="...industryCode=850121.SI">III海洋捕捞</a>
   ```
   `I/II/III` 前缀标记层级，秒级反查 symbol → 完整三级链

## 架构

新建 `src/data/industry_mapping_builder.py`（可导入、可测试、不依赖 akshare）：

| 函数 | 职责 |
|---|---|
| `fetch_taxonomy()` | 抓 overview 页，解析行业树 → `{三级码: (三级名, 二级名, 一级名)}` |
| `fetch_constituents(code)` | 拉单个三级行业成分股 → `list[str]`（symbol） |
| `rebuild_all()` | 遍历 335 个三级行业聚合全量映射，原子写 CSV |
| `update_symbol(symbol)` | 抓个股页行业链，更新/追加单行 CSV |

全量数据流：`fetch_taxonomy()` → 遍历 335 个三级行业 → `fetch_constituents()` → 每股归入 (一级, 二级) → 交叉校验成分股表"申万2级"列 → `style_category` 从 `申万_大类_映射.yaml` 查表 → 写 CSV。限速 0.3s/请求，全程约 8-10 分钟。

单只数据流：`/s/{symbol}` 页 `industry` 区块 → 解析 `I` 为 sw_level1、`II` 为 sw_level2 → 更新该行；symbol 不存在则追加。

合并策略：全量重建直接覆盖 CSV（legulegu 为权威源，000001 自然归入银行），构建后抽查验证。

## CLI / API 形态

**CLI**（`cli.py` 新命令组 `industry-mapping`）：
```
stock-robot industry-mapping            # 无参数 → 全量重建（rich 进度条 335/N）
stock-robot industry-mapping 000001     # 带股票代码 → 单只更新
```
进度回调复用 pipeline 的 `ProgressCallback` 模式。

**API**（`app.py`）：
```
POST /api/v1/industry-mapping/update   body: {"symbol": "000001"}   → 单只更新
GET  /api/v1/industry-mapping/{symbol} → 查询当前分类
```
同步执行（单只秒级），失败返回 404/422 语义化错误。前端暂不加按钮（YAGNI）。

## 错误处理

| 场景 | 行为 |
|---|---|
| 单次请求失败（网络/5xx） | 指数退避重试 3 次，仍失败则跳过并记录 |
| 单个三级行业抓取失败 | 跳过该行业计入 `failed_industries`，全量结束汇总报告 |
| overview 页结构变化（解析失败） | 立即中止全量并抛明确错误——结构变了全量数据不可信 |
| 成分股表"申万2级"列缺失 | 用该三级行业容器的 parent 链兜底 |
| 个股页无行业区块（新上市未分类） | 返回明确"未分类"错误，不写占位 |
| 磁盘写入 | 先写临时文件再原子替换（rename），中途失败不损坏现有 CSV |

覆盖率验收：全量结束统计成功/失败/跳过行业数 + 股票覆盖数，覆盖率 <95% 红色告警。
