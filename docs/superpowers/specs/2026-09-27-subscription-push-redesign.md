# 订阅推送重构设计

> 日期：2026-09-27  
> 状态：界面方案已确认，按本文实施  
> 需求来源：每日自动推送、网页管理订阅、查看进度与失败原因、试发邮箱；当前版本只支持邮箱，旧订阅和历史记录无需保留。

## 目标与边界

用户在配置页填写邮箱凭据，在订阅页试发测试邮件；验证成功后创建每日订阅。服务在指定时间生成每个标的的分析报告并发送。用户可以编辑、暂停、手动推送，并在页面查看每次运行的状态、进度和失败详情。

- 保留现有股票 `Pipeline`、指数 `IndexPipeline`、报告正文构建和 SMTP 后端；本次重构任务调度、执行记录、管理 API、CLI 与网页交互。
- 当前版本只提供邮箱发送。网页、API 和 CLI 不接受企业微信渠道，也不展示或要求企业微信凭据；发送器协议保留渠道扩展接口，未来再接入其他实现。
- 单个标的失败不阻断同一订阅的其他标的；默认不自动重试发送。SMTP 已接收但响应丢失时，自动重试可能重复发送。
- 不增加条件触发、其他发送渠道、报告预生成、并行分析或跨机器任务队列。

## 当前实现与改造原因

| 现状 | 影响 | 设计处理 |
| --- | --- | --- |
| 手动触发只返回 `triggered`，后台线程没有任务标识 | 页面无法区分排队、运行、完成和失败 | 创建运行记录后返回 `run_id`，页面轮询状态 |
| `push_runs` 仅在逐标的循环结束后写入 | 后端初始化失败或进程中断时没有完整记录 | 在执行前持久化排队记录，逐标的更新，异常统一收敛状态 |
| 同一订阅可被连续手动触发 | 可能重复发送，且与定时任务重叠 | SQLite 原子占位，同一订阅同时只允许一个活动运行 |
| 网页只能创建、启停和删除 | 无法编辑或查看失败详情 | 增加编辑表单、运行历史与详情 |
| 渠道只能通过完整研报试发 | 配置错误的反馈耗时且成本高 | 独立试发消息，不运行分析管道 |

## 网页流程

首页只显示一个主标题、右侧两个小按钮“邮箱设置”“新建订阅”，以及订阅列表。SMTP 表单与订阅表单默认不展开；点击按钮才打开对应弹窗。列表项只显示名称、标的摘要、每日时间、启用状态和最近一次结果，点击列表项进入详情，才显示运行历史及编辑、暂停、立即推送、删除等操作。

1. **邮箱设置弹窗**：填写 SMTP 与收件人参数，并提供“发送测试邮件”。按钮显示发送中、成功或可读错误。测试邮件清楚标注为测试，不包含股票研报。
2. **新建/编辑订阅弹窗**：默认只展示一个名称或代码搜索框、已选标的和每日时间；邮箱是唯一渠道，不展示渠道选择。输入部分名称、简称或代码显示候选，选中后加入列表；同一个输入框可粘贴多个代码。`000001` 等有歧义的代码必须选择具体候选，不猜测类型。订阅名称自动生成，编辑时保留已有名称，低显著度入口允许修改。指数风格由候选元数据决定，不在常用表单中填写。保存前展示已选项和数量上限错误；编辑时显式显示“保存修改”和“取消”。
3. **订阅列表**：每个标的前用带颜色且含文字的方形小标签标明“股票”或“指数”，后面显示 `600519（贵州茅台）`、`000300（沪深300）`、`HSI（恒生指数）` 等代码与名称。空间不足时显示前两个及“另有 N 个”，详情展示完整列表。名称无法解析时显示类型和代码，不猜测名称。股票名称在创建或编辑时批量解析并保存为显示快照；指数名称来自本地映射，打开列表不逐个请求 AkShare。
4. **订阅详情**：展示下次计划时间、完整标的列表、排队/运行中/成功/部分成功/失败/中断状态、已处理/总数、当前标的、开始及结束时间和逐标的失败原因。正在运行时定期刷新，离开订阅页后停止轮询，回到页面时重新读取服务端状态。
5. **操作边界**：暂停只停止未来定时执行，仍允许手动推送。同一订阅已有活动运行时，“立即推送”禁用并解释原因；编辑在下一次运行生效，当前运行使用开始时的订阅快照；运行中删除返回冲突提示。

标的类型保留 `auto`、`stock`、`index`，解决 `000001` 代码歧义。显示标识使用最终解析出的股票或指数类型，不能把 `auto` 直接显示给用户。若现有 API 使用逐标的不同类型，编辑页应保留每项原类型，不得把混合类型悄悄改写。搜索候选优先匹配代码前缀、名称开头，再匹配名称包含；股票名称表在进程内与磁盘缓存，输入时不逐字请求远端。已收录的海外指数（如 `HSI`、`SPX`）支持中文名称、常用简称和英文代码搜索，候选自动携带 `overseas` 风格；未收录的英文字母代码不直接加入订阅。

## 数据与状态

继续使用现有路径 `push.db`。用户未使用过该功能，旧订阅及运行记录无需保留；实施前仍需检查现有库结构，以非破坏方式完成结构调整，避免误删其他状态。数据库至少包含：

- `subscriptions`：`id`、`name`、`symbols`（JSON，含类型与显示名称快照）、`channel`（当前固定 `email`）、`time`、`enabled`、`created_at`、`updated_at`。
- `push_runs`：`id`、`subscription_id`、`trigger`（`scheduled`/`manual`）、`status`、`queued_at`、`started_at`、`finished_at`、`total`、`processed`、`ok`、`current_symbol`、`failures`（JSON）、`subscription_snapshot`。历史使用快照显示，即使后续编辑了订阅也不会改写旧记录。

状态流转：`queued → running → succeeded | partial | failed`；服务异常退出后，下一次启动将遗留的 `queued/running` 标为 `interrupted`，不自动重发。后端构造失败、分析失败和发送失败都进入同一运行记录。用数据库唯一约束阻止同一订阅出现两个 `queued/running` 记录，API 和调度器共用此约束。

每完成一个标的，写入 `processed`、`ok` 和失败详情；发送过程中 `current_symbol` 显示正在处理的代码。记录时间使用带时区时间戳；页面按北京时间显示。删除已结束订阅时，其运行历史可随订阅一并删除，因为用户不要求保留历史；运行中禁止删除。

## 调度与执行

- `stock-robot run` 启动后加载启用订阅，并为每条订阅注册北京时间每日任务；创建、编辑、暂停、恢复和删除后重载任务。
- 手动触发与定时触发共用一个提交入口：先原子创建 `queued` 记录，再启动执行器。手动 API 返回 `202` 和 `run_id`；已有活动运行返回 `409`。全局推送开关关闭时不注册定时任务，手动触发的行为需在实现前固定为允许或拒绝，避免页面语义不清。
- 调度器设置单订阅最大一个实例、合并积压触发，并限定短时误点火窗口。配置热重载只替换未来任务；已开始的运行继续使用启动时的配置和分析管道，不会被误标为中断。
- 服务关闭期间不能执行推送。本设计默认**不补发**错过的时段；服务恢复后只等待下一个计划时间。若需要关机后仍能定时推送，必须另设常驻服务或系统计划任务。

## API 契约

| 接口 | 用途与关键返回 |
| --- | --- |
| `GET /api/v1/subscriptions` | 列表，包含最近运行摘要和下一次计划时间 |
| `GET /api/v1/push/symbols?q=...&limit=8` | 搜索股票与已收录指数候选，返回代码、名称、类型、指数风格和市场；股票目录不可用时仍可按合法代码回退 |
| `POST /api/v1/subscriptions` | 创建，校验名称、标的、渠道、时间与数量上限 |
| `GET /api/v1/subscriptions/{id}` | 详情 |
| `PUT /api/v1/subscriptions/{id}` | 全量保存编辑和启停状态 |
| `DELETE /api/v1/subscriptions/{id}` | 删除；运行中返回 `409` |
| `POST /api/v1/subscriptions/{id}/run` | 手动运行；`202 {"run_id": 123, "status": "queued"}`，重复运行返回 `409` |
| `GET /api/v1/subscriptions/{id}/runs` | 最近运行列表，分页或限制条数 |
| `GET /api/v1/subscriptions/{id}/runs/{run_id}` | 单次运行状态、进度和失败详情 |
| `POST /api/v1/push/email/test` | 同步等待一条实际测试邮件的发送结果 |
| `GET /api/v1/push/status` | 全局开关、调度器状态和时区，供页面解释为什么未安排自动推送 |

邮箱试发在工作线程执行，避免阻塞 API 事件循环。配置不完整返回 `422`，发送失败返回可读但不含凭据的 `502`；服务端日志也不得记录 SMTP 密码。测试邮件的“发送成功”只表示 SMTP 服务接受请求，不代表收件人已阅读。

CLI 的 `subscribe add/list/remove/enable/disable/run` 应操作同一新数据库并沿用共同的运行记录入口。CLI 调用手动推送可同步等待并打印 `run_id`、最终状态和失败原因；网页与 CLI 不应各自实现一套独立执行逻辑。

## 验收标准

1. 用名称、简称或代码搜索并创建邮箱订阅；`000001` 给出股票/指数两个候选，`HSI` 与“恒指”指向同一海外指数。修改名称、标的和时间后，列表与下一次计划时间一致；暂停后不再注册定时任务，恢复后重新注册。
2. 试发测试邮件，模拟配置缺失、认证失败和网络失败；页面给出可操作反馈且不暴露凭据。页面及配置页不再展示企业微信凭据。
3. 手动运行返回 `run_id`，页面从排队显示到完成；逐标的成功/失败数准确，全部失败与部分失败可区分。
4. 同一订阅连续触发、手动与定时同刻触发时至多一个活动运行；不同订阅可独立运行。
5. 后端初始化异常、单标的异常、进程中断和运行中编辑/删除均有确定状态与回归测试。
6. 使用项目真实启动命令 `./.venv/Scripts/stock-robot.exe run --host 127.0.0.1 --port 8765`，在浏览器完成创建、编辑、暂停、试发失败反馈、手动触发及运行状态查看；窄屏与宽屏均无横向溢出。
7. 按仓库约定运行改动范围的 Ruff、Pyright、pytest；只有用户要求全量检查时才运行完整检查。

## 已采用的产品选择

1. 默认每天（含周末）按北京时间执行；服务关闭期间错过的推送不补发。
2. 全局推送开关关闭时，只关闭自动调度，仍允许用户主动试发和手动运行，并在页面明确提示。
