AstrBot 4.28.2 的隔离 WebChat 实例已验证默认 provider 首次复制、后台自举、沪深300及贵州茅台工具调用、图片实际加载，以及真实管理页停用再启用和进程清理。归档来自本机固定提交，未发布。完整时间、图片尺寸、命令和证据位置见实施计划的同日记录。

## 背景与目标

现状：插件（`D:\code\astrbot_plugin_stock_robot`）已通过 QQ 实测，可用，但要求用户**自己先把 stock_robot 服务跑起来**（`stock-robot run`），否则所有工具调用都回"分析服务未启动"。

目标：**用户只启动 AstrBot，插件自己把分析服务准备好。**

- 在受支持环境中首次自动准备：用户不填路径、不注册 PATH、不手动装依赖；网络、Python 版本和模型供应商兼容性仍有前提
- 已有服务在跑（用户自己启的、systemd 托管的、你本机那份）→ 直接复用，不重复启动、不误杀
- 否则 → **自举**：下载源码、建独立环境、装依赖、写最小配置、启动
- 同一套代码同时支持 Windows 与 Linux
- 只为"自用 + 预留发布"服务，不追求多用户/多实例管理

## 非目标（本期不做）

- 不做本机安装探测：**不读 PATH、不提供路径配置项**（见决策记录）
- 不做源码自动升级：完整实例复用；中断安装可在启用时恢复，extras 变化可补装
- 不做 AstrBot 模型配置持续同步或按会话切换；首次复制后由分析服务独立管理
- 不做进程守护/崩溃自动重启（调用期兜底已覆盖"挂了再拉起来"）
- 不做系统服务化、开机自启
- 不新增主仓 HTTP 端点；主仓只做依赖拆分与一处 `rag` 子命令的友好提示（见"主仓改造"）
- 不为发布做 GitHub 打包/插件市场提交（沿用上一份 spec 的发布预留章节）

## 决策记录

| 问题 | 结论 | 理由 |
|---|---|---|
| 服务来源 | **复用已在跑的服务；否则自举一份独立副本** | 不读 PATH、不提供路径配置项：用户不会把路径注册进 PATH，且省掉整套平台相关的探测/推导逻辑 |
| 取代码方式 | **httpx 下载固定 tag/commit 的源码归档**（不依赖 git） | 不以移动的 main 分支作为交付默认值；插件与服务组合可追溯 |
| 启动命令从哪来 | 插件从 base_url 推导 host/port，不新增 startup_port | 单一端口来源，避免监听与客户端端口不一致 |
| 进程生命周期 | **只关自己拉起的** | 复用用户手动启动的实例，避免误杀 |
| 触发时机 | **插件启用时启动 + 调用时兜底** | 启用即就绪；中途挂了/启动失败还能自愈 |
| 自举的 LLM Key | **首次尝试复制支持的默认 provider，之后由服务独立管理** | 不承诺跟随 AstrBot 换模型/换 Key；已有配置不覆盖，缺配置不重装程序 |
| 自举触发时机 | 只在**插件启用**时安装；调用限时等待已有任务，或启动完整已有副本 | 避免调用触发长耗时安装，保留服务崩溃后的兜底 |
| 依赖拆分 | **只拆 rag**（chromadb + sentence-transformers） | torch 那 2~3 GB 是 rag 独占；vectorbt/apscheduler 体积小，拆分收益不值当 |
| RAG 依赖的地位 | 移入 `[project.optional-dependencies] rag` | 插件的三个端点（analyze/index/reports）完全不用 RAG；主仓已有 try/except 守卫，代码零改动 |

### 服务来源（两级）

| 级别 | 条件 | 动作 |
|---|---|---|
| 1 | `GET {base_url}/health` 通 | **复用**。不启动、不记 `_owns_process` |
| 2 | 本机且 `auto_install` 为真 | 启用时确保完整实例再启动；调用时仅启动完整已有副本。持有自建进程句柄 |
| 3 | 级别 2 不可用或失败 | 保留失败原因，调用时回现状错误消息 + 诊断一句 |

`base_url` 指向远程主机（非本机）时**只做级别 1**：服务不在本机，插件无从启动。

`auto_install=false` 严格只复用：已有副本也不启动。自动启动仅限回环地址、无路径前缀的 HTTP URL；远程 HTTPS/带路径地址仍可复用。health 要求 HTTP 200、JSON 对象且 status=ok，不将任意 200 页面当成服务；此检查不是身份认证。

## 跨平台约定（Windows / Linux）

所有路径用 `pathlib` 拼接，平台差异集中在可执行路径及进程所有权辅助函数里：

| 关注点 | Windows | Linux |
|---|---|---|
| venv 内可执行 | `<venv>/Scripts/stock-robot.exe` | `<venv>/bin/stock-robot` |
| venv 内 python | `<venv>/Scripts/python.exe` | `<venv>/bin/python` |
| 建环境 | 优先 uv venv --python 指向 sys.executable；回退 sys.executable -m venv | 同；缺 python3-venv 时明确诊断 |
| 装依赖 | uv/pip 按 core/rag 清单执行 `--require-hashes -r`，再 `--no-deps -e .`（cwd = `instance/src`） | 同 |
| 起子进程 | `spawn_process` 封装 asyncio 创建；CREATE_NO_WINDOW + CREATE_SUSPENDED，先挂接 Job Object，再恢复运行 | asyncio 创建独立会话 start_new_session=True |
| 终止进程 | 关闭 KILL_ON_JOB_CLOSE 的 Job 回收自建进程树；父先退出也不遗留后代 | 自建进程组 SIGTERM，限时后 SIGKILL，并等待退出 |
| 日志路径 | `pathlib` 处理，无平台分支 | 同 |

## 组件与接口

新增两个模块，均**不依赖 astrbot**，可独立单测（与既有 `client.py` 同样的边界）。

### `launcher.py`

```python
class ServiceLauncher:
    def __init__(self, base_url: str, archive_url: str | None,
                 extras: str, auto_install: bool, timeout: float,
                 data_dir: Path, llm=None, runner=None, llm_loader=None): ...
    def start_background(self) -> None            # 启用阶段，立即返回
    async def ensure_ready(self, *, wait_timeout: float) -> ReadyOutcome
    async def stop(self) -> None                  # 只结束自己拉起的
    @property
    def state(self) -> Literal["idle", "starting", "ready", "failed", "stopped"]
```

- launcher 持有唯一准备任务，短临界区只保护创建；下载、安装、轮询不持有调用等待锁
- ensure_ready 限时等待 shield 后的共享任务；调用超时不取消后台任务、不改写后台状态。预算含 health、任务获取和等待
- 安装失败保留原因，调用期不重装；只有确认自建进程退出后，才可在后续调用重启
- 存活自建进程探测失败仅返回诊断并保留，不自动结束；初次启动就绪超时/提前退出则回收本次进程和句柄。存活引用不得被新引用覆盖
- stop 阻止新任务，取消并 await 准备任务，回收安装进程树和服务，再关闭日志；进程创建期间取消也须取得创建结果并回收
- 边界异常转为诊断，CancelledError 不吞掉，后台任务结果/异常必须被观察
- 子进程 stdout/stderr 经 PIPE 日志任务持续脱敏，追加写入 `{plugin_data}/astrbot_plugin_stock_robot/service.log`；完整行脱敏，超过 8192 字符的行整行略去，避免凭据跨块漏出；停用等待日志任务结束再关闭文件
- 健康探测（`GET /health`，超时 2s）作为模块级函数，便于单测

### `bootstrap.py`

四个独立入口，各自可单测、可返回明确失败原因；配置与程序安装分开编排。目录约定：`instance = {plugin_data}/astrbot_plugin_stock_robot/instance/`

1. `download_source(archive_url, instance)` — 流式下载至唯一临时文件，在同文件系统临时解压；先校验全部成员路径并拒绝链接，剥离顶层目录、验证 pyproject 后才发布 src。仅复用校验通过的源码
2. `make_env(instance, extras)` — 建 `instance/venv/`，按 core/rag 哈希锁清单安装，再以 `--no-deps -e .` 安装项目；extras 改回核心不会自动卸载旧 RAG 包
3. `write_config(instance, provider, port)` — 首次创建最小配置，支持的默认 provider 可复制 llm 字段；读不到则写 llm.enabled=false 并记录配置待完成。已有配置不覆盖
4. `ensure_instance(...)` — 只确保源码、环境和 CLI，不负责模型配置或服务启动；安装与 CLI 加载验证通过后原子写 install-state.json（格式版本、规范化 extras、源码来源及依赖安装策略）。安装完整性不依赖 Key、模型或配置文件

安装命令实时写日志，保留有限尾部和总截止时间（初始内部常量 20 分钟，探针校准）；取消/超时回收自建命令及子进程并等待退出。无 pip 的 uv 环境回退前检查 ensurepip。模型配置失败单独诊断，不撤销安装标记、不重新安装。配置文件不能解析时提示修复原文件，不覆盖；缺模型配置的服务允许确定性分析降级，验收时必须另行确认 LLM 解读可用。

手工实施时将 runner 的日志路径通过 partial 绑定。模型读取通过可选异步 llm_loader 注入，只有启用后台任务首次创建配置时执行；initialize 不等待 provider。晚就绪有界重试初始为 10 秒，探针后校准；失败也不阻止安装完成。复制仅支持已核实的默认 provider，主仓后端名是 openai、claude；不将未知供应商默认为 openai，不按会话切换。复用外部服务不读、不改它的配置。首次复制后换模型/Key需在自举服务 Web UI 修改；若未配置则给出操作地址，后续重载也不覆盖现有文件。

### 源码与依赖版本

- 默认归档固定到阶段 A 改造完成、实际验收通过的 tag/commit，具体引用待探针回填；没有已验收引用时不得以 main.zip 冒充稳定默认值。
- 首选安装策略：由 uv.lock 导出 core/rag 两份带版本和哈希的 requirements 清单，随源码归档提供；自举用 uv 或 pip 安装指定清单，再以 --no-deps 安装项目，避免重新解析业务依赖。uv 可执行参数已由本机 help 核实，跨平台实际安装仍是待验证门禁。
- 下载成功时把实际 URL/SHA256 写入 src/.bootstrap-source.json，与完整源码一起发布；安装标记引用该记录，方便中断恢复。自定义归档也须符合安装契约，来源变化不触发自动升级。SHA256 用于追溯，不代表可信发布签名。
- 本期不扩展为自动升级器；如果清单策略无法满足目标环境，先记录具体阻塞并调整设计，不静默回退到无锁安装。构建工具依赖和平台 wheel 可用性一并在探针中记录。

### `main.py` 挂钩

| 位置 | 动作 |
|---|---|
| `initialize()` | 创建 launcher，调用 start_background，立即返回；main 不额外持有启动任务 |
| `_run_analysis()` 入口 | 先发送准备消息，再限时 ensure_ready；失败发一条诊断并返回，不重复 client 错误消息 |
| `terminate()` | await launcher.stop，finally 关闭 client；正常重载等待旧任务和进程退出 |

## 触发规则与时序

### 插件启用（`initialize`）

1. 立即创建后台任务并返回
2. 后台：health 探测 → 通则结束（复用）；否则 ensure_instance（必要时下载+安装）→ 独立准备首次配置 → 启动 → 轮询就绪。缺模型可降级，配置错误不触发重装
3. 用户调用先收到准备提示，然后限时等待共享任务；预算取 startup_timeout_seconds 与 AstrBot 剩余工具超时较小值，并预留发送诊断时间。超时不取消安装，提示查看日志

### 工具调用

1. 先探测，健康则复用；stopped 拒绝新任务
2. 已有共享任务则限时加入，绝不重复启动
3. 没有任务、本机且开关开启、程序安装完整时允许启动；已持有存活进程但不健康时只诊断，不重启。配置缺失/损坏与安装失败分别提示，不将配置问题解释为未安装
4. 调用不下载、不安装、不修复配置；失败只发一条含诊断的消息并提前返回

### 插件禁用 / 重载（`terminate`）

- 先阻止新任务，取消并等待准备任务与安装进程树退出，再结束自建服务（terminate → 等 5 秒 → kill）；重复停用幂等，清理失败保留句柄和诊断
- 重载 = 杀自己那份 + 重新探测（若用户手动启动的实例在跑，级别 1 会复用，不受影响）

## 自举细节

- 目录：`instance/` 下 `src/`（源码）、`venv/`（独立环境）；`cwd = instance/` → 生成 `instance/.stock_robot/config.yaml` 与 `instance/reports/`
- 幂等：完成标记与源码、环境、入口、extras 有效才算安装完成；配置另行处理。配置变化不触发安装，中断安装仅在启用时恢复
- 压缩包：GitHub 归档 ZIP 自带顶层目录（如 `stock_robot-main/`），解压时剥掉，使 `instance/src/pyproject.toml` 直接成立；下载大小随仓库而定（估几 MB ~ 几十 MB）
- LLM Key：首次尝试复制已核实默认 provider，之后在自举服务管理；明文配置不输出日志、不提交
- 依赖：默认核心依赖（含 vectorbt、apscheduler），不含 `rag`；`bootstrap_extras=rag` 时才装 RAG
- 耗时预期：核心依赖首次安装数分钟；失败时保留安装器输出最后若干行作为原因摘要

## 错误处理

| 场景 | 处理 | 用户可见 |
|---|---|---|
| `base_url` 非本机 | 只做级别 1 | 现状消息 |
| 压缩包下载失败（网络/404） | 记录状态码与异常摘要 | "分析服务安装失败：{摘要}（详见插件日志）" |
| 解压或建环境失败 | 记录输出尾部 | 同上 |
| 装依赖失败 | 记录安装器输出最后若干行 | 同上 |
| 子进程立即退出（端口占用等） | 读 stderr 尾部 | "分析服务启动失败：{stderr 尾部一行}" |
| 就绪超时 | 记 `startup_timeout_seconds` 与日志路径 | "分析服务启动超时（{n} 秒），详见插件日志" |
| 调用期不触发安装 | 不在调用时下载/装依赖 | "分析服务未就绪（可能在安装中），详见插件日志" |
| 全失败 | 保留原因 | 现状"分析服务未启动"消息 + 诊断一句 |

## 测试

文件预算：插件只新增 test_bootstrap.py、test_launcher.py，main 挂钩和包导入断言并入后者；主仓复用 test_cli_rag.py。相近场景参数化，共用假件，不为每个辅助函数建文件。只保留一个真实小型 HTTP 子进程冒烟，动态端口、有界轮询、finally 回收。

关键回归：单飞明确统计安装/spawn 次数；安装中调用限时返回但后台继续；安装中停用/重载回收进程树；初次启动超时回收，运行期探测失败不结束存活进程；关闭开关不启动；配置缺失不撤销安装标记；中断恢复与来源记录；按正式包结构导入。仍集中在两个测试文件，pytest 使用唯一项目 tmp 目录。

**单元（不依赖 astrbot、不依赖网络）**

- health 探测矩阵：通 → `reuse`；不通 + `auto_install` → 走自举；不通 + `auto_install=false` → `failed`；`base_url` 非本机 → 只探测
- 命令与路径拼装：按平台产出 `Scripts/stock-robot.exe` 与 `bin/stock-robot`（用参数注入平台，而非真的换系统）
- 单飞：并发两次 `ensure_ready` 只产生一个子进程（用假可执行脚本计数）
- `stop()`：只结束自己拉起的；复用场景下不动别人的进程
- 配置写出：临时目录 + 假 provider 数据 → 断言 YAML 的 `llm` 段与 `api.port`
- 幂等：完整实例跳过安装；中断安装启用时恢复，extras 不匹配启用时补装
- 解压安全：成员路径含 `../` 的恶意压缩包被拒绝

**集成（TEMP 假件，不碰真实环境）**

- 假 stock_robot：一个 Python 脚本起 http server 返 `/health` → 验证就绪轮询、超时、子进程提前退出三条路径
- 自举：内存 ZIP 与假 Runner 验证下载、原子发布、剥离顶层目录、编排失败和恢复，不真装大依赖；不为自举单独增加真实 HTTP 服务测试

1. **核心依赖能否启动服务并完成一次分析**：拆掉 `rag` 后照 `pyproject.toml` 装核心依赖，实测 `run` + 一次 `analyze`（重点看 `api/bootstrap.py` 之外是否还有隐式 RAG/重依赖导入）

## 已知限制

- Windows 实现使用 Job 对象及父退出监视回收自建进程树，已做专项探针；本轮真实 WebChat 只覆盖正常停用，未再次强杀 AstrBot。Linux 正常退出与强杀行为需目标机补验
- 国内网络下下载源码与装依赖可能失败；`source_archive_url` 可指向镜像，但**没有内置镜像默认值**
- 只支持公开可匿名下载的归档 URL（插件不发凭据），私有仓库需自建带鉴权的下载地址
- 自举副本与你 `D:\code\stock_robot` 那份互不共享：配置、`reports/`、缓存都是各自的
- 不做自动升级。手动重装先停用并确认自建进程退出，仅重建 src、venv 和安装标记；保留 .stock_robot、reports 及数据库。操作前备份状态，服务新版本的数据格式兼容性须检查，不删除整个 instance
- Linux 路径未在真实机器上验证（本机为 Windows），验收需在目标机补跑
