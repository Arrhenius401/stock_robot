日期：2026-11-18。状态：设计已确认，实施交由 codex 执行。

## 1. 状态与授权

2026-11-18 用户确认以下方向：

- 解读部分以 A 股 v2 结构化解读为标准。
- 统一范围是"报告结构 + 解读结构"；数据缺口按市场声明，不强行拉平。

## 2. 现状

### 2.1 已统一

- Markdown 只有一份模板 `src/report/templates/report_v2.jinja2`，CLI、API、Agent 和报告库共用 `build_report` / `build_stock_payload`。
- 五维评分、覆盖率、信号门槛是共用框架。
- 每个市场都有数据质量表和免责声明。

### 2.2 未统一

- A 股额外分析模式使用 v2 结构化解读：主营业务、核心结论、五维解读、风险提示、解读限制；模型返回严格 JSON，带证据引用和数字/操作词校验。
- 港股和美股仍使用 `src/llm/prompt_templates/batch_analysis_common.jinja2` 的自由文本，只有三段式正文，没有主营业务、程序五维短句、风险候选和解读限制。
- `src/core/pipeline.py` 只在 A 股额外分析模式设置 `commentary_version = 2`；`src/report/research.py` 的 `resolve_research` 对非 A 股直接返回 `None`。
- 市场差异散落在 `src/report/builder.py`、`src/report/scoring.py`、`src/report/quality.py`、`src/report/templates/report_v2.jinja2`、`src/report/research.py`、`src/llm/market_context.py` 和 `src/api/static/js/report-renderer.js`。

## 3. 目标与非目标

### 3.1 目标

1. 三市场使用同一报告骨架和同一 v2 解读结构。
2. 市场差异收口到 `MarketProfile` 和 `research_rules`，模板与 Web 不再按市场名分叉。
3. 缺数据状态统一：区分"不适用""未采集""采集失败""样本不足"。
4. 用东财 F10 补港美主营业务；美股年度作为参考期进入报告，银行专项作为事实进入报告。
5. A 股现有输出逐字不变；评分公式、权重、信号阈值和覆盖率分母不变；旧归档不改写。

### 3.2 非目标

- 美股舆情采集、相关性过滤和情绪评分。
- 港股半年/年度财报转 TTM。
- 保险专项指标和 BRK.B 收入映射。
- 美股年度参与行业评分，或银行专项接入财务评分。
- 指数、黄金、雷达、推送和插件。
- 重写历史报告或引入通用报告 DSL。

## 4. 统一框架

### 4.1 MarketProfile

新增 `src/report/market_profile.py`，三市场各一份冻结配置，作为市场规则与文案的唯一来源。

| 字段 | 说明 |
|---|---|
| `key` / `label` | `a-shares` / `hk` / `us`，显示名 |
| `industry_scheme` / `industry_note` | 申万一级 / 恒生 HSICS / 东财美股 F10 |
| `period_basis` | `quarterly_ttm` / `report_period` / `ttm` |
| `currency_guard` | 是否需要"币种未核实不比较金额"约束 |
| `sentiment_policy` | `scored`（A）/ `news_or_assessed`（HK）/ `not_collected`（US） |
| `signal_policy` | `data_gated`（本期三市场一致） |
| `business_profile` | 适配器与来源文案，例如 `ths` / `f10_hk` / `f10_us` |
| `annual_industry_policy` | `scored`（A/HK）或 `reference_only`（US） |
| `financial_special_policy` | `none` 或 `facts_only`（US 银行） |
| `disclaimer` | 免责声明段落 |
| `prompt_rules` | 注入 v2 模型提示词的市场规则 |
| `limitation` | 解读限制的固定文案 |

模板、Web payload、prompt、quality 都消费该配置。删除新报告路径上的 `market == "hk"` 分支；旧报告兼容分支保留。`profile_for` 接收 `a-shares` / `hk` / `us`；`profile_for_label` 接收报告展示名 `A 股` / `港股` / `美股`，供旧调用兼容。`build_disclaimer` 保留旧签名包装，内部转 profile。

### 4.2 ResearchReport v2

三市场统一输出：

```json
{
  "version": 2,
  "market": "a-shares|hk|us",
  "profile_version": 1,
  "business_profile": {
    "symbol": "",
    "status": "ok|unavailable",
    "source": "",
    "source_label": "",
    "fetched_at": "",
    "main_business": "",
    "reason": ""
  },
  "dimensions": [
    {
      "key": "financial",
      "label": "财务健康",
      "text": "程序规则短句",
      "rule": "financial.cash_support",
      "status": "available|partial|not_applicable|not_collected|unavailable",
      "reason": "",
      "evidence_ids": ["financial"]
    }
  ],
  "evidence": {},
  "risk_candidates": [],
  "model": null,
  "limitation": ""
}
```

- `dimensions` 固定五项：财务、技术、估值、行业、舆情。
- `text` 由纯函数规则生成，模型不能修改。
- `model` 只接受固定字段：`business`、`conclusion{overall,support,question}`、`evidence_ids`、`risks[]`。
- 模型失败或校验失败时保留确定性五维和主营资料，不显示伪造的核心结论。

### 4.3 CapabilityStatus

每个维度用两个维度表达，不把"缺失"压成一个布尔值：

| 轴 | 取值 | 说明 |
|---|---|---|
| `applicable` | true / false | 市场或行业规则是否适用 |
| `coverage` | complete / partial / none | 实际数据覆盖 |
| `reason` | `market_policy` / `not_collected` / `collection_failed` / `insufficient_sample` / `industry_na` / `period_unverified` | 不适用或缺失的原因 |

示例：

- 美股舆情：`applicable=false, reason=not_collected`，文案为"本期未采集可评估样本，不能据此判断风险水平"。
- 港股非港股通：`applicable=false, reason=market_policy`，文案为"不参与港股行业对比"。
- 美股银行财务：`applicable=true, coverage=partial, reason=industry_na`，文案为"通用指标不适用，银行专项仅展示事实"。
- A 股行业样本不足：`applicable=true, coverage=none, reason=insufficient_sample`，文案为"同期有效同行证据不足"。

该状态只影响展示与解读，不改变覆盖率公式和评分。

### 4.4 渲染按数据形状与状态

模板和 Web 不再按市场名判断，按字段形状判断：

- 有 `risk_score` 或五维评分模式：渲染舆情评分卡。
- 额外分析且 `sentiment_policy == "not_collected"`（美股）：渲染通用新闻事实并明确"本期未计分"。
- 客观模式：渲染通用新闻事实列表。
- 旧版港股（无五维评分）：保留港股新闻参考列表。
- 有 `comparison`：渲染同行表。
- 有 `signal`：渲染信号；没有则渲染 `signal_unavailable_reason`。
- 市场名只用于标题、行业口径、免责声明和 prompt 规则。

### 4.5 数据流

```text
AnalysisContext + results
        |
        v
MarketProfile（分类/期间/币种/舆情/信号/主营/免责声明）
        |
        v
ResearchReport v2（主营业务、核心结论、五维解读、风险提示、解读限制）
        |
        +--> Markdown（report_v2.jinja2）
        +--> Web payload（research_commentary -> report-renderer.js）
```

## 5. 市场解读规则

### 5.1 A 股

保持现有 v2 规则不变，作为基线：

- 财务：亏损、利润与现金流背离、现金覆盖、收入/利润同比、ROE。
- 技术：完整均线与 MACD 方向。
- 估值：自身采样分位与同行分位，分位不等于高低估。
- 行业：最新期与完整年度两期。
- 舆情：风险分、评估状态、样本限制。

### 5.2 港股

- 财务按报告期描述，不把半年/年度称为季度，不推导未经验证的 TTM。
- 金额币种未核实时只陈述事实，不做金额同比、现金流趋势或与港币行情混算。
- 行业使用恒生 HSICS，非港股通标的不参与行业对比。
- 舆情只有新闻时，文案为"相关可评估样本不足，暂不能判断整体舆情风险"，不能写成零风险。
- 解读限制追加：历史估值仅代表采样区间；同行按同报告期比较；舆情只覆盖已采集样本；财报按报告期，币种未核实时不作金额比较。

### 5.3 美股

- 财务使用 TTM；银行/保险通用指标不适用时明确说明，银行专项只展示事实。
- 行业评分只使用 TTM 最新期；完整年度作为参考期展示，不参与评分。
- 行业分类使用东财美股 F10，不是 GICS/申万。
- 舆情本期未采集/未计分，文案必须保留"不能视为零风险"。
- 解读限制追加：年度为参考期；金融专项为事实；美股评分未做历史回测校准。

### 5.4 风险候选与解读限制

- 风险候选仅来自程序证实的风险事实，例如财务亏损、背离、下降或估值分歧。数据不足、采集失败、币种或报告期未核实等均属于数据限制。
- 「数据覆盖与时效」说明美股舆情未采集、年度仅供参考、银行专项仅展示事实；对应舆情、行业、财务三行。
- 模型只能引用候选风险；不能新增未提供的风险 ID。
- 解读限制由 `MarketProfile.limitation` 和数据质量限制共同生成。

## 6. 数据补齐

### 6.1 港美主营业务

探针已验证（2026-11-18）：

- 港股 `RPT_HKF10_INFO_ORGPROFILE` 含 `MAIN_BUSINESS`、`ORG_PROFILE`、`ORG_NAME`、`SECUCODE`、`SECURITY_CODE`、`BELONG_INDUSTRY` 等字段；00700.HK 返回 1 行，`MAIN_BUSINESS` 为完整业务描述。
- 美股 `RPT_USF10_INFO_ORGPROFILE` 含 `ORG_PROFILE`、`ORG_NAME`、`SECUCODE`、`SECURITY_CODE`、`BELONG_INDUSTRY` 等字段；AAPL 返回 1 行，`ORG_PROFILE` 为业务描述；美股无 `MAIN_BUSINESS`。
- 两者均可用 `columns=ALL`，按 `SECUCODE` / `SECURITY_CODE` 过滤；探针在带/不带环境代理下均成功。

设计：

- 扩展 `src/data/business_profile.py` 为 `load_business_profile(cache, symbol, market, refresh=False)`。
- 港股：`MAIN_BUSINESS` 优先，`ORG_PROFILE` 兜底。
- 美股：`ORG_PROFILE`。
- 校验证券身份、`ORG_NAME`、内容非空、长度上限；清洗首尾空白和连续空白。
- 新增 `source_label`：A 股"同花顺主营介绍"，港股/美股"东财 F10 公司资料"。
- 缓存键包含市场与代码，TTL 7 天，单次请求，超时 8—10 秒；失败返回 `status=unavailable` 和原因。
- 主营文本不得用于收入占比、分部收入或业务结构推断；F10 叙述只作业务简介。

文本处理：

- 模型返回的 `business` 优先。
- 无模型时，源文本不超过 160 字直接使用；A 股保持现有"超过 160 字显示主营资料已取得，简要介绍暂不可用"行为；港股/美股超过 160 字时取第一句或按标点截到 160 字。
- 只有源资料缺失时才显示"主营业务资料暂不可用"。

### 6.2 美股年度参考期

探针已验证：`RPT_USF10_FN_GMAININDICATOR` 和 `RPT_USF10_FN_BMAININDICATOR` 均含 `DATE_TYPE=年报` 行；GMAIN 有 `OPERATE_INCOME_YOY`、`NET_PROFIT_RATIO`、`ROE_AVG`，BMAIN 有 `TOTAL_INCOME_YOY`、`ROE`、`ROA`。单位均为百分数。

设计：

- `src/data/us_operating.py` 在现有 TTM 记录中追加 `annual` 子对象，不改变 TTM 平铺字段，避免破坏现有消费者。
- 年度记录包含 `start`、`end`、`basis="FY"`、`source`、`currency`、`notice_dates`、`revenue`、`net_profit`、`revenue_growth_yoy`、`net_margin`、`roe`。
- `src/data/enrichers/us_industry_enricher.py` 构造 `periods.annual`，带 `reference_only: true`、`label: "完整年度（参考）"`；`periods.latest` 保持 TTM。
- `comparison` 增加 `score_periods: ["latest"]`，`src/analysis/industry_scoring.py` 只对 `score_periods` 内的期计分，并跳过 `reference_only` 期。
- A 股/港股不传 `score_periods`，继续年度 40% + 最新 60%。
- Web 行业切换默认选中 `latest`；年度标签显示"完整年度（参考）"并注明"仅参考，不计分"，不能把参考期当计分期。
- 报告与解读把年度放在"参考"位置，不能把年度和 TTM 混成同一期。

### 6.3 美股银行专项

探针已验证：BMAIN 年度行含 `NET_INTEREST_INCOME`、`LOAN_LOSS_PROVISION`、`LOAN_DEPOSIT`、`LOAN_ASSETS`、`DEPOSIT_ASSETS`、`ROE`、`ROA`。`LOAN_DEPOSIT` 为 0—1 比率，`ROE`/`ROA` 为百分数。

设计：

- `src/data/us_operating.py` 为 BMAIN 增加 `special` 事实：
  - `net_interest_income_ratio_pct = NET_INTEREST_INCOME / TOTAL_INCOME * 100`
  - `provision_to_revenue_pct = LOAN_LOSS_PROVISION / TOTAL_INCOME * 100`
  - `loan_to_deposit_pct = LOAN_DEPOSIT * 100`
  - `loan_to_assets_pct = LOAN_ASSETS * 100`
  - `roe_pct = ROE`
  - `roa_pct = ROA`
- 只使用语义明确的字段，不推导净息差、不良率、拨备覆盖率。
- 金融维度展示"银行专项指标（来源：东财 F10 BMAIN，年度）"，不改变财务分和信号。
- 行业比较可在 `comparison.financial_special` 展示目标与同行的专项中位数，但不进入 `score_industry_comparison`。
- 保险（BRK.B）BMAIN 无数据，保持 N/A 并说明"保险专项未接入"。

## 7. 提示词与模型

- `model_prompt(ctx, research, profile)` 统一 JSON schema，追加 `profile.prompt_rules` 和 `profile.limitation`。
- A 股提示词文案保持现状，不能因新增 `market` 或 profile 字段而改变；港股/美股在基础提示词后追加市场规则。
- 港股提示词强调报告期、币种未核实、HSICS、新闻样本限制。
- 美股提示词强调 TTM 最新期、年度仅参考、银行专项仅事实、舆情未采集、非 GICS/申万。
- 无主营资料时 `business` 必须为空；有资料时不得补造分部收入或收入占比。
- 数字校验沿用 `parse_model`：模型只能引用事实中出现的数值；证据 ID 必须属于本批次。校验前对事实和模型文本统一去掉千分位逗号，只做同一数值归一，不剥离单位或百分号。
- 模型失败时保留确定性五维和主营资料，不增加修复调用。

## 8. 兼容与降级

- `commentary_version = 2` 扩展到三市场；旧上下文仍为 1，继续走 legacy bulk。

- 模型失败、未配置、未启用时，Web 与 Markdown 都显示"来源资料与程序生成的五维定性"或对应量化摘要。
- 旧报告不改写；`legacyHk`、旧 bulk、旧 `commentary_status` 分支保留。

## 10. 风险与未决

- F10 `MAIN_BUSINESS` / `ORG_PROFILE` 是叙述性资料，不是收入拆分；不能据此推断分部收入。
- 美股年度是参考期，不参与评分；若未来要参与，需单独校准 40/60 权重和信号阈值。
- 银行专项只补事实，不形成评分；专用评分器和保险专项另立项目。
- 港美模型输出 JSON 的稳定性尚未实测；失败时依赖确定性降级。
