# 股票池结果与补全界面

## 已确认范围

2026-11-12 用户确认聊天中的浅色交互预览。沿用项目最终生效的浅色 CSS 变量、池选择器和任务窗口。此项目接续结构化股票池能力的网页接入；10 月管理页面与结构化数据项目文档保留为历史，不追改。

- 首页默认展示当前池已通过的前 20 家，提供全部列表、搜索、状态筛选和分页。状态栏显示已筛选、通过、待检验、落选数量；补全按钮独立靠右。
- 规则随池切换，默认前 5 条，可展开收起；区分共同条件、风格条件及提醒，解释实际规则和版本，不能将机会门槛冒充筛选淘汰线。
- 补全窗口先展示服务器绑定计划、公司、条件、来源、年份/窗口和自动补全能力，再允许全部执行。无待补项时禁用。
- 更新、补全均后台执行，窗口显示阶段与实际已处理/总量，支持桌面拖拽、调整大小、收起恢复；窄屏不允许窗口移出屏幕。切页不取消任务，返回恢复状态，错误可见且可重试。
- 更新期间保留上一次完整结果；成功复核后整体切换。旧响应不能覆盖其他池。未解决项保留，缺失不判失败。
- 详情复用公司证据与条件结果；筛选通过不等于正式成员。正式发布始终关闭，不调用 LLM，不改规则与行业映射，不 push、不注册自动任务。

## 后端接入事实

已有 evaluate_store(structured_only=True)、来源 loader、StockUpdateRunner/Store、build_completion_plan、apply_plan、recheck_run。命令行补全已支持正式 provider，但当前网页无筛选结果快照、计划及补全长任务接口；需要服务层接入，不新写采集旁路。不以忽略目录中的最终产物硬编码线上结果。

新接口统一在 `/api/v1/radar/stocks`：按池查询 screening、screening/rules；启动 screening/update；读取 completion/plan、提交 completion/apply；读取 screening/tasks/latest 和 screening/tasks/{run_id}。结果使用 items/total/page/page_size/counts/as_of/rule_version；计划用 SHA 绑定确认时的内容，变更返回 409。
