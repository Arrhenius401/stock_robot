# 配置雷达实施计划

**目标：** 实现收盘后本地快照驱动的配置雷达。首期使用国内及港股、海外两个独立 ETF 池；通用核心预留受限股票池以及可复现的低频多标的回测。

**架构：** 新建独立 `radar` 包。`RadarDataProvider` 按 `asset_type` 注册实现；首期 AkShare ETF 专用适配器经此协议归一化后，刷新器在受限速保护下写入 `.stock_robot/radar.db` 的不可变完成态快照；CLI 和 API 只读取快照。后续 Web 仅消费 API，不属于本期。回测以历史日线在调仓日即时重算信号，独立写入 `reports/radar_backtests/`，不改写现有单股 `backtest` 契约。

**技术栈：** Python 3.11、Pydantic v2、Click、SQLite、pandas、AkShare、FastAPI、原生 JavaScript、pytest。

**设计：** `docs/superpowers/specs/2026-09-05-配置雷达设计.md`

## 全局约束

- `radar` 核心支持 `asset_type: etf | stock`，首期启用人工审核的 `cn_hk_etf` 与 `overseas_etf`；二者不得混排。不做全市场、盘中实时、杠杆/反向/单股 ETF 或自动交易。
- CLI/API 查询不得直接触达 AkShare/Tushare；只有刷新任务可以访问提供者。后续 Web 同样只能通过 API 读取结果。
- 首版总评分仅用可从历史日线回放的趋势、回撤、波动和流动性。折溢价/净值/跟踪误差只展示，不进入决策。
- 每次刷新必须生成新的不可变 `run_id`；未完成快照永不可见；失败时诚实标记 `stale`/`failed`。
- ETF 回测只能使用当日及以前的数据，并在下一交易日开盘成交；无数据、不能成交或基准失败必须明确失败。
- 代码注释和新增文档使用中文。Python 命令统一使用 `.venv/Scripts/python -m pytest`；每任务只跑相关测试、Ruff 与单文件 Pyright。

## 文件结构

| 文件 | 职责 |
|---|---|
| `config/radar_universes/cn_hk_etf_v1.yaml`、`overseas_etf_v1.yaml` | 人工审核标的池、类型、分类、生效日和流动性门槛。 |
| `config/radar_strategies/core_rotation_v1.yaml` | ETF 评分权重、窗口、月度再平衡和成本档引用。 |
| `src/radar/models.py` | 通用池、策略、快照、评分、刷新/回测请求模型。 |
| `src/radar/universe.py` | YAML 加载、版本/生效日选择和按类型准入校验。 |
| `src/radar/data.py` | 通用提供者协议、首期 AkShare ETF 适配、日线/现货归一化、限速。 |
| `src/radar/store.py` | SQLite 快照运行、观测、原子完成态与查询。 |
| `src/radar/scoring.py` | 按评分配置注册的纯因子函数和研究等级。 |
| `src/radar/refresh.py` | 增量/全量刷新、失败隔离、旧观测降级。 |
| `src/radar/backtest.py` | 按池类型的多标的低频回测；首期 ETF 月度调仓。 |
| `src/api/radar.py` | 快照、刷新任务和回测结果 API 路由。 |
| `src/api/app.py`、`src/stock_robot/cli.py` | 挂载预留 API 与 `radar` 命令组。 |
| `tests/radar/`、`tests/api/test_radar.py` | 不联网测试夹具与 API 验收。 |

## Task 1：冻结通用标的池契约与 ETF 首池

**Files:** 新建 `src/radar/models.py`、`src/radar/universe.py`、`config/radar_universes/cn_hk_etf_v1.yaml`、`config/radar_universes/overseas_etf_v1.yaml`、`config/radar_strategies/core_rotation_v1.yaml`、`tests/radar/test_universe.py`。

1. 先写失败测试：重复代码、非法类别、无 `effective_from`、杠杆/反向标记、同一池 ID 的重叠生效区间必须拒绝；指定日期返回正确的池版本。
2. 实现 `RadarUniverse`、`RadarInstrument`、`RadarStrategy` 与 `UniverseRepository.active_on(date)`；模型必须持有 `asset_type` 与 `score_profile`，策略指纹遵循现有 `backtest.strategy_fingerprint` 的规范化 JSON + SHA-256 短哈希语义。
3. 固化 22 个已审核代码：国内及港股、海外各自独立配置；测试仅使用 3–5 个虚构/夹具代码，不把未审核代码当成生产池。
4. 运行 `.venv/Scripts/python -m pytest tests/radar/test_universe.py -q`；随后对两个新文件运行 Ruff 和 Pyright。

## Task 2：通用数据提供者与首期 ETF 适配

**Files:** 新建 `src/radar/data.py`、`tests/radar/test_data.py`；可能修改 `src/data/akshare.py`，仅当复用低层请求/重试实现能避免重复时。

1. 先用本地 AkShare 安装环境检查并记录实际接口签名/返回列；实现前以小规模、手动执行的只读网络探针确认 `fund_etf_spot_em`、`fund_etf_hist_em`、`fund_etf_fund_info_em` 的字段与覆盖率，探针不进入测试。
2. 定义 `RadarDataProvider`：`supports(asset_type)`、`fetch_spot()`、`fetch_daily(symbol, start, end)`、`fetch_nav(symbol, start, end)`；返回项目 Pydantic/标准 DataFrame，不泄露上游字段名。首期实现只声明支持 `etf`，股票提供者在未来单独注册。
3. 实现可注入时钟的串行令牌桶与提供者熔断：默认 1 请求/秒；429/403 或连续解析失败停止本轮同源调用；网络异常按项目既有退避策略处理。
4. 固定夹具测试日期、OHLCV/成交额列名归一化、空响应、限速、403/429 和不完整日线。运行关联 pytest、Ruff、Pyright。

## Task 3：不可变本地快照存储

**Files:** 新建 `src/radar/store.py`、`tests/radar/test_store.py`；修改 `src/utils/config.py` 增加 `radar` 配置（刷新窗口、限速、数据库路径、最小历史覆盖）。

1. 先写 SQLite 测试：创建 `running` run 后查询不可见；`complete_run` 后原子可见；写入异常不污染上一份完成快照；`stale` 观测保留来源 run ID。
2. 创建 `snapshot_runs`、`snapshot_items`、`factor_values` 三张表与必要索引。每个写入事务使用临时状态，完成时一次更新 `completed_at/status`。
3. 实现 `latest_completed()`、`get_snapshot(run_id)`、`copy_latest_healthy_item()` 和 `status_summary()`；任何编辑旧 `completed` run 的 API 均不存在。
4. 跑 `tests/radar/test_store.py` 和配置测试，执行 Ruff/Pyright。

## Task 4：评分与等级

**Files:** 新建 `src/radar/scoring.py`、`tests/radar/test_scoring.py`。

1. 先写固定日线测试：20/60 日趋势、60 日最大回撤、20 日年化波动、20 日均成交额；验证只使用截点及以前数据。
2. 实现类别内百分位、权重汇总和 `偏好/观察/谨慎/unavailable` 等级。任一必需因子缺失或类别样本少于 3 时不得生成伪排名。
3. 测试同分、分类隔离、权重变化导致指纹变化、缺失值、覆盖期不足和等级阈值；运行关联检查。

## Task 5：刷新服务与 CLI 命令组

**Files:** 新建 `src/radar/refresh.py`、`tests/radar/test_refresh.py`；修改 `src/stock_robot/cli.py`、`tests/test_cli.py`。

1. 先写测试：默认增量只请求缺失/过期区间；`--full` 才重建窗口；一个标的失败时从最近完成快照降级并标 `stale`；所有标的失败时 run 失败且旧快照仍可读。
2. 实现 `RadarRefresher.refresh(universe_id, mode, as_of)`，严格串行调用 provider，完成原始数据、评分、快照三阶段后才提交 run；先按池的 `asset_type` 选择提供者与 `score_profile`。
3. 增加：
   - `stock-robot radar universe list`
   - `stock-robot radar refresh --universe <池ID> [--full] [--as-of YYYY-MM-DD]`
   - `stock-robot radar status --universe <池ID>`
   - `stock-robot radar show --universe <池ID> [--run-id] [--category]`
   首期已启用两个池，`--universe` 必须显式传入。禁止增加与池配置重复的 `--type` 参数。
4. CLI 必须调用既有免责声明检查；输出数据日期、run ID、成功/过期/失败计数，失败使用非零退出码。运行关联 pytest、Ruff、Pyright。

## Task 6：预留只读 API 与刷新任务接口

**Files:** 新建 `src/api/radar.py`、`tests/api/test_radar.py`；修改 `src/api/app.py`。

1. 先定义并测试 API：`GET /api/v1/radar/universes`、`GET /api/v1/radar/snapshots/latest?universe_id=...`、`GET /api/v1/radar/snapshots/{run_id}`、`POST /api/v1/radar/refresh`、`GET /api/v1/radar/refresh/{task_id}`。读取端点仅访问 `RadarStore`；刷新请求必须携带 `universe_id`，后台线程同一时刻只允许一个任务。
2. API 响应显式包含“研究评分，不构成投资建议”、数据截至时间、池/策略版本和 `fresh/stale/failed` 状态；不得返回或渲染任意未经净化的上游 HTML。
3. 运行相关 API 测试，覆盖无快照、部分失败、旧快照回退、重复刷新冲突和请求参数校验。Web 页面、静态资源与浏览器验收明确推迟到后续任务。

## Task 7：ETF 多资产历史回测

**Files:** 新建 `src/radar/backtest.py`、`src/radar/artifacts.py`、`tests/radar/test_backtest.py`、`tests/radar/test_artifacts.py`；修改 `src/stock_robot/cli.py`、`src/utils/config.py`。

1. 先写固定多 ETF 日线夹具：月末评分只消费历史窗口、下一交易日开盘成交、类别冠军等权、没有合格标的时现金、池版本切换、费用和基准失败。
2. 使用 ETF 专用请求/结果模型；不要扩大 `BacktestRequest`/`BacktestStrategy` 以适配 ETF。ETF 卖出成本不得继承股票印花税。
3. 复用既有运行 ID、原子目录写入和五类产物思想，但输出路径固定为 `reports/radar_backtests/<资产类型>/<策略ID>/<池ID>/<YYYY-MM>/<run-id>/`；`manifest.json` 必须保存池版本、资产类型、策略指纹、调仓日、费用和数据范围。
4. 新增 `stock-robot radar backtest --universe <池ID> --strategy ... --start ... --end ... [--benchmark ...]`；日期/策略/池/基准无效时先失败且不创建结果目录。
5. 运行 ETF 回测测试、Ruff 与 Pyright。仅在数据端点经人工确认后，执行一次实际 CLI 回测作为非确定性烟测，并记录数据源与日期。

## 验收清单

- [ ] API 和 `radar show` 从本地完成态快照读取，查询期间零上游请求。
- [ ] `radar refresh` 默认增量、受速率限制、可恢复部分失败；`--full` 明确触发重建。
- [ ] 每份快照与每次回测都能追溯池版本、策略指纹、数据时点和失败状态。
- [ ] 首版排名不使用不可回放的净值/折溢价字段。
- [ ] ETF 回测遵守 point-in-time 池、历史数据和下一交易日成交，输出完整可审计产物。
- [ ] API 可完成刷新和结果读取；未创建 Web 页面，未产生自动交易功能或收益承诺。
