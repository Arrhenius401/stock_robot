# 配置雷达自动采集重构实施计划

日期：2026-09-30

当前范围：设计、计划与交互预览；界面确认后实施。所有新增文件名为建议名称，实施时按已有职责调整。

## 已完成的无副作用探针

- 当前 `.venv`：APScheduler 3.11.3，FileLock 3.32.4。
- `CronTrigger(hour=18, minute=30, timezone='Asia/Shanghai')` 的下一触发时间包含 `+08:00`。
- FileLock 提供 `timeout`、非阻塞获取与上下文管理器，采用现有依赖，不新增锁框架。
- AkShare 的 `tool_trade_date_hist_sina()` 当前签名为无参数并返回 DataFrame；此次仅检查签名，未访问网络，年份覆盖待数据探针验证。
- 启动目录与项目状态取 cwd，进程命令必须显式固定项目根。
- 当前不存在标的池 `enabled` 与自动行情补齐服务。

## 0. 实施准备与基线（B）

1. 确认预览的信息结构与弹窗交互。
2. 用 managed worktree 创建独立实施工作树；以已提交基线为起点，将现有未提交自动采集修复整理为单独补丁并审查后带入。
3. 不带入用户的 AGENTS.md、文档目录整理及无关格式变动；不复制密钥和数据库进入 Git。
4. 在 Windows 工作树内跑相关原有测试，记录基线；启动进程固定路径和项目状态目录，避免与当前服务争用。
5. 为日期、进程和数据源注入接口；Linux 真实环境未提供前保留平台验收未完成状态。

对象：`radar/models.py`、`universe.py`、`collector_store.py`；新增采集任务模型及迁移测试。

2. 原位扩展 SQLite 计划、任务、项级记录、租约、事件与运行信息；保留旧审计。

命令：`.venv/Scripts/python -m pytest tests/radar/test_collector_store.py tests/radar/test_universe.py -q`，改动文件 Ruff/Pyright。

## 2. 交易日历与目标日选择（A）

对象：新增 `radar/calendar.py`、缓存表和日历测试。

1. 实测 AkShare 日历返回列、年份范围和时区，记录首个完整失败原因。
2. 先写收盘前后、周末、连续假日、跨年、缓存覆盖不足与网络失败测试。

5. 同一函数供自动、手动、恢复与下一次计划计算使用。

## 3. 行情补齐与完整池评分（S）

对象：`radar/data.py`、`refresh.py`、`store.py`；新增行情存储与同步模块。

1. 先用真实异常格式与确定性数据写缺口、乱序、重复、陈旧尾行、复权变更和部分源失败测试。
2. 核实各提供者的历史覆盖与价格口径，定义缓存键与校验结果，不根据提供者名称猜复权方式。
3. 实现范围读取、缺口识别、重叠更新和实际覆盖记录；CSV 保持独立来源。
4. 改造刷新为“准备行情 → 校验 → 整池评分 → 不可变发布”，传入明确目标日期。
5. 失败项重试只重新请求失败行情；成功数据用于完整池排名重算。
6. 保留全失败不发布、部分失败注明 stale/failed、健康快照可读取的原行为。
7. 小区间历史表现/回测复用已覆盖行情，补齐阶段不运行池级策略。

验证：行情/刷新/快照/表现相关定向测试；分别做需求审查与代码质量审查，修复后复审。

## 4. 独立协调器与统一任务执行（S）

对象：`radar/collector.py`、新增 worker/executor、`stock_robot/cli.py`。

1. 先写双进程争锁、原子认领、进程中断恢复、重复触发和执行中关闭测试。
2. 独立服务持有单实例锁，更新心跳，在关闭采集时继续待命。
3. 每轮从最新设置和启用池协调最近目标日期，持久成功记录决定是否跳过。
4. 单独执行锁与任务租约保证 CLI 和队列共同互斥；不只依赖 APScheduler 的进程内 max_instances。
5. 关闭时取消自动排队/重试，正在执行项到安全边界停止；所有网络请求有超时。
6. 默认三次尝试，终止配置错误，记录中断与失败原因；手动任务独立于自动开关。
7. 新 daemon/once/status 命令使用同一执行器，路径固定；保留旧 CLI 的清晰兼容说明。

验证：真实子进程配合临时数据库测试锁与恢复；需求审查、质量审查、修复后复审。
