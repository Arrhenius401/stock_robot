# 订阅推送重构实施计划

> 对应设计：`docs/superpowers/specs/2026-09-27-subscription-push-redesign.md`  
> 状态：待实施  
> 约束：用户已确认邮箱优先、`push.db` 原路径、精简首页与弹窗交互；保留其他渠道的后端扩展接口，不在当前界面或 API 暴露企业微信。

## 实施前探针结果

- `CronTrigger(hour=8, minute=30, timezone=ZoneInfo("Asia/Shanghai"))` 在当前 `.venv` 可用，计算的下一次触发为带 `+08:00` 时区的时间。
- `utils.symbols.resolve_name()` 每次会调用 AkShare 获取代码名称表；列表接口不能逐标的调用。`IndexMapping.lookup()` 使用本地映射。股票名称应在保存订阅时批量解析一次并持久化快照，失败时保留类型与代码。
- 当前 `RuntimeManager.reload()` 会构建候选快照并切换调度器；已开始运行必须继续持有旧快照，只有进程初始启动时才能恢复遗留的活动运行。

## 任务 1：模型与存储

- 调整 `src/push/models.py`：当前渠道只允许 `email`，标的增加显示名称快照；输入仍兼容代码字符串和字典。显示类型必须为解析后的 `stock` 或 `index`。
- 在 `src/push/store.py` 的既有 `push.db` 中增加运行状态字段与原子占位方法；保存 `queued/running/succeeded/partial/failed/interrupted`、触发来源、进度、当前标的、失败详情和订阅快照。对旧空库安全升级，不删除数据库文件。
- 同一订阅至多一个 `queued/running`，使用 SQLite 事务或唯一约束保证。提供运行列表、详情及初始启动恢复中断运行的方法。
- 测试创建、更新、重复占位、进度、状态、历史、删除和恢复。验证两个独立 `PushStore` 实例的竞争边界。

## 任务 2：名称解析与执行调度

- 新增批量名称解析层：指数本地映射、股票批量获取名称；保存时解析，不在列表读取时联网。解析失败不阻止订阅创建，页面显示类型和代码。
- 执行器从同一运行 ID 开始逐标的发送，成功或失败后写进度；后端初始化失败也能收敛为失败记录。保持单标的失败隔离，发送不自动重试。
- 定时与手动使用同一占位和执行入口。调度明确使用北京时间；重载只影响未来任务，初始启动才标记上次进程中断的运行。
- 测试手动/定时同刻触发、旧运行时快照继续工作、失败隔离和中断恢复。

## 任务 3：API、CLI 与邮箱试发

- 将订阅管理从 `src/api/app.py` 拆到独立路由，接口以设计稿为准。手动运行 `202` 返回 `run_id`，重复运行 `409`；提供运行列表/详情、推送总状态和测试邮件接口。
- 邮箱试发使用真实 SMTP 后端发送轻量消息，在工作线程执行；配置错误与发送错误给出不含密码的反馈。
- `src/api/configuration.py` 和设置页仅暴露邮箱推送配置，不再展示企业微信凭据；保留通用发送器协议，移除当前版本可触达的企业微信路径。
- CLI 共用新的 store/runner；手动运行打印运行 ID、完成状态和失败原因。
- API 与 CLI 测试覆盖 CRUD、校验、试发错误、运行状态、错误码和凭据不泄露。

## 任务 4：精简订阅页

- 首页只保留标题、`邮箱设置`、`新建订阅` 两个按钮和订阅列表；复用当前浅色主题与侧栏，不重绘全局布局。
- 两个按钮分别打开弹窗；订阅详情集中放完整标的、历史与操作。列表标的格式为 `（股票）600519（贵州茅台）`、`（指数）000300（沪深300）`，缺名时只显示类型和代码；超过两项折叠为“另有 N 个”。
- 弹窗支持键盘关闭、焦点返回、错误提示；运行期间只轮询当前可见订阅页，切走后停止。保留迟到请求令牌避免旧响应覆盖新状态。
- 样式使用共享 `--page-inset`，桌面 24px、窄屏 12px、最大 980px；更新 CSS/JS 缓存版本。避免覆盖工作区中现有页面布局改动。

## 任务 5：验证与审查

- 对改动文件运行 Ruff、单文件 Pyright 与相关 pytest；按项目约定，未要求全量检查时不跑全量。
- 通过 `.venv/Scripts/stock-robot.exe run --host 127.0.0.1 --port 8765` 启动真实服务，浏览器完成创建、编辑、暂停、邮箱试发失败反馈、手动触发与运行状态查看。无真实邮箱凭据时不发送外部测试邮件，用可控测试配置验证成功路径。
- 宽屏与 390px 窄屏测量各功能页标题和首组件位置，检查水平溢出、遮挡并查看截图。
- 进行一次规范审查和一次代码质量审查，修复后复审关键路径；保留用户原有未提交改动。
