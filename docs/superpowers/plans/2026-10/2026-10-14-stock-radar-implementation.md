# 配置雷达股票池分阶段实施计划

日期：2026-10-14。依据：[功能设计](../../specs/2026-10/2026-10-13-stock-radar-functional-design.md)。状态：已确认界面及业务流程的实施计划；数值规则尚待集中确认。不是实施完成报告。

## 1. 授权、事实与边界

用户已确认完整分层预览，包括分组搜索选择池、切换区仅保留选择与更新、业务入口进入内容区、行业概览、简洁列表、折叠详情及管理流程。股票两池名称、持续盈利、行业龙头、黑五类排除、共享候选库、审核发布、手动更新和自动默认关闭已确认。

代码调查使用CodeGraph，定位到：

- `src/api/static/js/allocation-view.js`：`allocationHeader`目前创建原生select，`allocationShowList`按照ETF快照分组，`allocationShowDetail`有快照及历史路由。
- `src/api/static/js/api.js`：ETF池、快照、采集、回测与单标的表现请求独立存在。
- `src/api/radar.py`：`/universes`从`UniverseRepository`加载配置；人工更新使用`UpdateService`，已有服务生命周期与持久任务。
- `src/radar/models.py`：`RadarUniverse.instruments`至少一项；`RadarScoreProfile`固定ETF四因子，不能把空股票池或股票规则塞进原模型。
- `scripts/verify.ps1`支持`-VenvPath`和`-Files`，只按改动范围验证。新配置会被通用映射到CLI测试，新股票配置需补明确映射。

因此采用统一只读池目录、独立股票模型和股票API分支。保留原ETF配置、接口、快照、评分和回测语义；不放宽原模型校验。研究脚本中的名单和常量不能直接变成生产成员。

3. 对新增模型、API、状态边界测试先行。新增资源放`tests/resources/radar/`，完整响应和截图留忽略目录。
4. 按项目分级执行：跨前后端及API为S级，完整规格与质量双审查、修复后复审；边界独立模块A级合并单审查；小修复B级主会话直接处理。
5. 每个阶段必须具有独立价值和清晰验收；同一事项的源码、测试及文档合为本地提交，不逐控件提交。不推送、合并或发布。

## 3. 阶段一：池目录、正式切换组件和空股票池

独立价值：在真实雷达中替换原生下拉框、保留ETF全部功能，并显示可扩展的两股票池入口与真实空状态。此阶段不是股票筛选功能完成。

### 任务1：只读池目录与股票定义（S级）

新增建议文件`src/radar/pool_catalog.py`、`src/radar/stocks/models.py`、`src/radar/stocks/pools.py`，新股票定义置于`config/radar_stock_pools/`，成员不写入配置。

池目录描述字段：稳定`id`、`name`、`asset_type`、`description`、`display_order`、`capabilities`；股票定义保留`rule_version`或未配置状态。目录从ETF现有配置及股票定义组合，不在前端硬编码四个名称。不同类型ID冲突报明确配置错误；坏配置不得造成股票路由悄悄读取另一池。

测试先行：

- 空股票池合法，原ETF空池仍非法。
- 添加第三个股票配置后目录自动出现，禁用配置不作为可选项；名称及排序来自配置。
- 股票不要求ETF score_profile，不输出综合评分。
- 目录查询不触发行情、公告、网络请求或写入成员。
- 类型、标识符、重复配置与缺失必要字段得到明确错误。

### 任务2：API目录与空态（S级）

新增建议`GET /api/v1/radar/pools`作为统一目录；原`/universes`继续保持原响应。股票池定义查询与成员查询沿用设计中的stocks分支，由独立仓储提供空集合，不伪造快照或研究成员。行业聚合为空，返回明确成员数和功能准备状态。

尚未配置规则或未实现采集时，“准备候选”和股票更新必须明确显示暂不可用原因，不能按钮假成功、空任务已完成或调用ETF刷新。此限制仅阶段一临时状态，后续阶段补齐真实功能。

测试先行：旧ETF接口兼容；不存在ID返回404；空池返回正常空集合；股票请求不调用ETF Provider／ScoreProfile；规则未配置无法启动正式筛选；只读查询不新建后台任务。

### 任务3：选择组件与视图分支（S级）

新增建议`src/api/static/js/radar-pool-picker.js`和股票视图模块；接入`allocation-view.js`、`api.js`及既有静态入口，更新脚本和CSS缓存版本。

- 组件只显示当前池与类型，面板按类型分组、搜索名称与用途、选中打勾、列表内滚动。
- 上下键选择、Enter切换、Esc／外部点击关闭、焦点返回入口，弹层内Tab循环；窄屏底部弹层。
- 切换栏仅选择和更新。ETF“查看海外动态”进入ETF内容区；股票“候选与成员管理”进入股票内容区。
- 初次默认原国内及港股ETF池，历史ETF hash仍能恢复指定快照及详情；不能把股票ID传给ETF快照和更新API。
- 保存当前池及各池浏览状态。切换时使用请求令牌丢弃迟到响应，不能显示前一池数据。
- 股票首次真实为空，不导入演示股票；加载和错误都有可见状态与重试入口。

验证：静态资源测试只验证模块加载与兼容约束，真实交互必须在项目服务中验收，不用字符串断言替代交互。

### 任务4：真实服务验收与阶段交付

从实施工作树启动`D:\code\stock_robot\.venv\Scripts\stock-robot.exe run --host 127.0.0.1 --port 8765`，先确认editable导入路径指向工作树；如果仍指向主仓库，使用已验证的工作树启动方式并记录，不拿主仓库旧代码验收。

浏览器覆盖池搜索、四池切换、空股票池、错误与重试、ETF详情及返回、历史快照、海外入口和实际更新任务；完成一次真实会话发送与响应，保持正文／思考事件语义。

宽屏与390px检查共享坐标、面板边界、无水平溢出及遮挡；页面涉及全局CSS时按AGENTS逐页测量股指个股／指数、雷达、报告库、订阅、日志和配置。ETF图表至少一次同日双线悬浮，核实单标的表现与池级策略文案、基准、成本和成交记录仍保留。

建议相关测试：`tests/api/test_radar.py`、`tests/api/test_static.py`、`tests/api/test_radar_updates.py`、`tests/api/test_radar_update_ui.py`、新增池目录与股票API测试，以及`tests/radar/test_universe.py`。最终按实际改动选择必要范围，不能宣称未执行的项通过。

## 4. 阶段二：共享资料、规则、证据与研究脚本迁移

开始正式数值评估前集中确认功能设计第3、4、6节剩余参数。未确认门槛保持待配置，不默认放行。

1. 新增带来源、期间、公告时点的股票数据模型和仓储。复用既有SQLite，新增stocks前缀表，成员、证据、发布及风险事件分开保存。
2. 把研究脚本转为参数化采集适配器与CLI，支持截点、分阶段缓存、失败清单、续跑与可审计原始来源；两池及未来其他池共享同公司采集。
3. 确定性共同准入引擎：持续盈利、规模、流动性、审计治理、金融分支、行业及龙头证据。数据缺失为待核验，监管认定造假排除，不能LLM自动放行。
4. 独立风格与机会引擎：同股双池；季报拆分、利润基数、分红实施、股类币种、市值历史、估值覆盖及收益基准口径。
5. 把旧研究只导入来源索引和未核验事实，失效数据重取。685初筛、238优先对象及数值交集均不是成员。

测试覆盖真实异常样本、公告截点、累计／独立季度、金融、A/H口径、未知状态、条件边界；与阶段一目录和股票读接口连通。具体适配器接口及资源预算确认后再补逐文件任务，不对未经探针的外部API编造调用方法。

## 5. 阶段三：成员发布、生命周期与后台任务

1. 审核记录带revision，硬条件不能人工绕过；未保存不发布，过期revision返回409。
2. 批量成员变更原子发布，保存前后成员数、理由与生效时间；新增与恢复审核发布，允许空池及超过30家，不自动补位。
3. 已核实共同资格失效同时作用两池并立即停止有效展示；暂停、风格移除、机会观察分别处理。旧数据回写不能恢复已退出成员。
4. 统一变更清单按公司合并共同风险、保存未解决事项并更新证据，价格变化不生成强制待办。
5. 股票任务复用现有任务服务的基础机制，但独立任务类型与快照。区分更新当前池、发现候选；同请求幂等，两池共享采集、限流失败、任务续跑、成员发布版本校验。
6. 手动任务可用；自动默认关闭，不注册新的系统任务。启用频率和证据有效期确认后再接自动调度。

测试：并发发布、同股双池、失效和恢复、旧快照、任务中切换、重试与限流、部分失败、重启续跑、不重复通知。后台正常任务必须以真实服务验收，不能仅用预览计时器。

## 6. 阶段四：完整股票流程与首批成员

接入实际行业概览、全池搜索、适用指标排序分页、详情折叠、候选管理、变更清单、证据编辑及未保存保护、发布前后预览。参数和数据缺失在页面明确显示。

首次准备候选 → 完成证据审核 → 选择首批关注对象 → 发布。用户未选择前保持空池，不为了展示功能预填研究对象。实现筛选与管理不隐含授权代用户发布最终关注名单。

真实服务验证首次空池、准备任务、候选审核、冲突、失败、发布、暂停／退出、恢复、详情返回原筛选及页码；检查两个ETF池完整兼容，复核图表及全站布局。阶段一结果可复用，只重复新改动和受影响范围。
