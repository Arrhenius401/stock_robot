# 运行时配置热更新实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 配置页以本地草稿集中保存；保存后让新任务安全使用新运行时配置，且不影响正在执行的任务。

**Architecture:** 新增 `RuntimeManager`，以加锁的不可变 `RuntimeSnapshot` 承载 `Config`、`AgentCore`、推送执行器和调度器。配置 API 先校验并写盘，再在锁外构建新依赖、在锁内原子替换快照；HTTP/SSE/推送入口各在开始时读取一次快照。设置页仅维护本地脏状态，并通过顶部粘性保存条一次提交全部改动。

**Tech Stack:** Python 3.11、FastAPI、APScheduler、Pydantic、pytest、原生 ES modules/CSS。

**Spec:** `docs/superpowers/specs/2026-08-27-运行时配置热更新设计.md`

## Global Constraints

- 代码注释、文档和 Git 提交信息使用中文；提交格式遵循 `type(功能点): 简述`。
- 所有 Python 命令使用 `.venv/Scripts/python`；Ruff 使用 VS Code bundled 二进制；pyright 使用 `pyright`。
- 不使用裸 `except Exception`；第三方 SDK 或运行时构建隔离边界可捕获，但须记录日志并带 `# noqa: BLE001`。
- `api.host` 与 `api.port` 只写入配置，必须重启 `stock-robot run`；不得试图迁移正在监听的 Uvicorn 套接字。
- 热更新只影响保存成功后开始的新任务；已开始的聊天、SSE、分析和推送任务必须继续持有旧快照。
- 不向公开 API 响应、日志或浏览器错误消息输出完整密钥。
- 本计划基于当前未提交的设置页单列/密钥输入框改动继续修改，不得覆盖或回退它们。

- [ ] **Step 3: 实现 `RuntimeSnapshot`、`ReloadResult` 与 `RuntimeManager`**

在 `src/api/runtime.py`：

```python
class RuntimeManager:
    def __init__(self, config: Config, core: AgentCore | None, push_store: PushStore | None,
                 *, core_factory: Callable[[Config], AgentCore] = build_agent_core,
                 executor_factory: Callable[[AgentCore, PushStore, Config], PushExecutor] = PushExecutor,
                 scheduler_factory: Callable[[PushExecutor, PushStore, Config], PushScheduler] = PushScheduler):
        self._lock = threading.Lock()
        self._core_factory = core_factory
        self._executor_factory = executor_factory
        self._scheduler_factory = scheduler_factory
        self._snapshot = self._build_snapshot(config, core, push_store)

    def snapshot(self) -> RuntimeSnapshot:
        with self._lock:
            return self._snapshot

    def reload(self, config: Config) -> ReloadResult:
        try:
            candidate = self._build_snapshot(config, None, self.snapshot().push_store)
        except (ValueError, RuntimeError, OSError) as exc:
            logger.warning("配置热更新构建失败: %s", exc)
            return ReloadResult(applied=False, error="运行时配置构建失败")
        with self._lock:
            previous = self._snapshot
            self._snapshot = candidate
        self._start_candidate_and_shutdown_previous(candidate, previous)
        return ReloadResult(applied=True)
```

实际实现须避免在锁内执行 core 构建、scheduler `start()` 或 `shutdown()`；`push.enabled=False` 时候选快照保留 scheduler 对象但不启动。为避免 `build_llm()` 当前吞掉初始化异常，给 `build_llm` 增加 `strict: bool = False` 参数，并在 `build_agent_core(config, strict_llm=True)` 下将 SDK 初始化错误作为具体 `RuntimeError` 抛出；CLI 和现有调用保持默认降级语义。
