# 验证与提交检查

由根目录 `AGENTS.md` 按任务触发读取；适用内容具有同等约束力，不需在每次任务中加载其他主题。

## 检查时机

- 全量检查耗时约 4 分钟（ruff 数秒 + pyright ~1 分钟 + pytest ~3 分钟），**默认不要在每次任务中自动运行**
- 全量检查安排在合并或发布前，或用户明确要求“全量检查/全量回归”时；普通“检查一下”“提交一下”按改动范围验证，不自动触发全量。
- 开发过程中先执行单文件检查和相关模块测试，代码稳定后再做必要的门禁；相同代码状态已验证通过的范围可以复用结果，不因分笔提交重复执行。
- 检查失败时先保留异常和失败清单，定位到单个用例或模块；修复后优先复核失败用例及受影响范围。只有证据表明影响扩大或存在明确验收门禁时才重复全量。
- 日常编码依赖 IDE 实时诊断；**修复循环中不要反复跑全量 pyright**，优先秒级单文件检查：
  - `pyright <文件>` 或 `pyright <文件1> <文件2>`（单文件约 2 秒，只检查改动波及的文件）
  - `ruff check <文件>`
  - `.venv/Scripts/python -m pytest <测试文件> -q`
- pyright/ruff 输出量大时先聚合（`--outputjson | python 汇总为 行号+规则+摘要`），避免原始输出灌入上下文
- 涉及类型系统边界行为（Protocol/ClassVar 结构匹配、`cast` 到 Literal、`# pyright: ignore` 规则码）先用 10 行临时探针 + `pyright <探针>` 验证再大规模应用
- `mcp__ide__getDiagnostics` 依赖 IDE 连接，时有时无，**不可作为复查依赖**

推荐入口为 `.\scripts\verify.ps1 -Scope Changed`；它按 Git 改动选择相关验证集，**不会自动回退全量**。提交前使用 `-Source Staged`，全量必须显式使用 `-Scope Full`。可加 `-PlanOnly` 查看 JSON 检查计划而不运行工具。无法归类的代码会退出并提示用 `-Files` 指定相关源码/测试，记录覆盖范围；不能把未覆盖的改动表述为验证通过。

## 环境事实

- `python`/`pip` 裸命令指向 Anaconda（`D:\Private File\Anaconda`）——**所有 Python 命令显式用 `.venv/Scripts/python`**；Anaconda 缺 pytest-asyncio，用它跑 async 测试会误报失败
- 首次开发环境同步执行 `.\scripts\bootstrap-dev.ps1`；它将 Ruff、Pyright、pytest 固定到 `.venv`，不依赖 VS Code 扩展或用户目录中的全局工具。
- 环境探测合并为一条命令（`which python ruff pyright`），不要逐个探测

## 提交检查

- 动手提交前先核对范围，按完整事项组织提交：相关源码、测试、正式设计/部署文档一并收敛，避免单独拆出零碎文档提交；preview、截图、缓存、日志、配置凭据和测试产物默认不提交。`docs/superpowers/previews/` 已忽略，保留本地预览即可。
- 仅文档、忽略规则或移除 preview 的改动：执行 `git diff --cached --check`，不重跑业务测试。
- 普通代码提交：执行 `.\scripts\verify.ps1 -Scope Changed -Source Staged`，或复用同一代码状态已通过的相关检查，并补 `git diff --cached --check`。暂存文件应与验证时的工作区内容一致，验证后再修改必须复核受影响部分。
- 跨模块重构、依赖/配置变化：本地提交执行相关模块测试和必要冒烟验证，说明尚未覆盖的范围；合并或发布前执行 `.\scripts\verify.ps1 -Scope Full`，要求全量 Ruff、Pyright、pytest 通过。
- 提交时不隐式启动全量门禁，不重复已完成的真实服务和浏览器验收。前端/会话改动仍须满足 [Web 与会话验收](web.md)。

## 测试静态资源

- 离线数据统一放在 `tests/resources/<业务模块>/`，不另建分散的 fixtures 目录。
- 文件名使用小写来源、标的代码与内容类型，以连字符分隔；必要时追加时期，保留真实扩展名。
- 样本来源、采样日期、裁切范围及解析口径写入所属项目已有计划；小修复没有计划时写在测试注释及提交信息中，不为样本补建文档。资源目录不放 README。
- 测试资源随测试提交；完整响应、缓存、日志和截图留在忽略目录 `tmp/`。
- 资源变更须在 `verify.ps1` 中映射到相关模块测试，不能静默跳过。

## 测试临时目录与失败处理

- Pytest 每次运行使用项目内唯一临时目录，例如 `tmp/pytest/<范围>-<PID>-<GUID>/basetemp`，缓存也归入同一次运行目录；不要重用固定目录或仅用 PID 命名，避免旧权限和占用影响检查。
- 所有正在运行的测试结束后再清理缓存，不能一边运行一边递归删除测试目录。成功运行后尝试删除本次目录，失败产物先保留用于诊断；不要把测试产物提交。
- 缓存清理与代码提交分开处理。清理权限错误只记录未清理路径，不推翻已通过的检查，也不阻断无关代码提交；不为删除缓存擅自修改 ACL，不重复尝试已被审批拒绝的权限变更。
- 全量测试失败时必须保留首个完整异常和失败测试清单，区分本次改动与既有失败；不能将“命令被执行窗口截断”或“输出为空”表述为测试通过。
